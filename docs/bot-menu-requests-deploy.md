# Обновление VPS: меню бота и обращения к администратору с согласием

Инструкция для Claude Desktop. Пути, домен, имена сервисов и логины — свои вместо
`<…>`. Секреты (ключи, токены, пароли) не выводить в чат, не коммитить и не писать в
журналы. Развёртывание — только по решению владельца.

## 1. Что меняется

- **Меню бота** — три действия: «Открыть приложение» (кнопка ВКонтакте `open_app`,
  открывает VK Mini App 54834865 в контексте сообщества 242364009), «Мои записи»,
  «Администратор». Кнопки «Цены», «Врачи», «Адрес», «Записаться онлайн» убраны —
  пациент пишет это текстом, ИИ в переписке работает как раньше.
- **Обращение к администратору:** пациент пишет, что нужно решить → бот показывает
  точный текст → «Разрешаю передачу» / «Не разрешаю» → текст попадает в панель,
  раздел «Обращения» (только роль «Администратор»). Отзыв — «отозвать передачу».
  Подробности — `docs/medical-privacy.md`, раздел 6.
- **Миграция базы v7** — таблицы `patient_requests` и `request_access_log` (с
  триггерами неизменности текста). Записи, врачи, расписание, сотрудники, пароли,
  согласия врачу не меняются.
- Ограничение остаётся: руководители сообщества ВКонтакте видят исходную переписку
  независимо от согласия. В текстах бота это сказано прямо.

## 2. Сначала выяснить, что сейчас на сервере

В каталоге проекта, под пользователем, от которого запущены бот и панель:

```bash

node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync(process.argv[1],{readOnly:true});console.log('схема v'+db.prepare('PRAGMA user_version').get().user_version)" "${BOT_DB_PATH:-.data/bot.sqlite}"
npm run admin:user -- list              # роли сотрудников (после v6) или просто логины (v5)
```

- Схема **v5** (`a27d677`): это обновление включает этап 2 (роли, v6) — сначала прочитать

- Схема **v6**: этап 2 уже стоит; Mini App, вероятно, тоже (`docs/vk-mini-app-deploy.md`).

## 3. Резервная копия (обязательно)

```bash
npm run db:backup                       # → ../bot-backups/bot-<дата>.sqlite, без остановки бота
ls -la ../bot-backups/ | tail -3
cp -p .env.local ../bot-backups/env.local.<дата>   # chmod 600; отдельно от копий базы, если там ключ
```

## 4. Переменные окружения (`.env.local`)

| Переменная               | Нужна для                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| `VK_MINIAPP_ID=54834865` | бот: кнопка «Открыть приложение»; Next.js: Mini App. Без неё у бота — «Записаться на приём»        |
| `VK_MINIAPP_SECRET`      | только Mini App (проверка подписи). Уже задан, если Mini App открывается                           |
| `MEDICAL_DATA_KEY`       | шифрование и **обращения с согласием**. Без него «Администратор» работает по-старому, без передачи |
| `VK_GROUP_ID=242364009`  | уже есть; `owner_id` кнопки `open_app`                                                             |
| `VK_ADMIN_USER_ID`       | уведомления администратору ВКонтакте (ссылка на диалог и номер обращения, без текста)              |

Ключ `MEDICAL_DATA_KEY`, если его ещё нет, создать на сервере (значение не выводить):

```bash
grep -q '^MEDICAL_DATA_KEY=' .env.local && echo "ключ уже есть — не менять" || \
  node -e "console.log('MEDICAL_DATA_KEY=' + require('crypto').randomBytes(32).toString('base64'))" >> .env.local
chmod 600 .env.local
```

Существующий ключ **не менять**: зашифрованные разговоры и согласия станут нечитаемыми.

## 6. Перезапуск

Перезапустить **бота** и **панель** тем же способом, каким они запущены
(`systemctl restart <бот>` и `systemctl restart clinic-admin` или `pm2 restart …`).
Миграция v7 применяется один раз тем процессом, который первым откроет базу.

В журнале бота — `схема v7`, `long poll: connected`, `кнопка «Открыть приложение»: да`,
`обращения с согласием: да`. Если `нет` — проверить `VK_MINIAPP_ID` и `MEDICAL_DATA_KEY`.

## 7. Сотрудник для «Обращений»

Раздел «Обращения» видит только роль **«Администратор»** (не владелец и не врач — так
по тексту согласия). Если в панели только владелец: «Сотрудники» → «Пригласить» →
роль «Администратор» → передать одноразовую ссылку сотруднику лично. Или на сервере:
`npm run admin:user -- create <логин> --role=admin` (пароль вводится скрыто).

## 8. Проверка на реальном телефоне

Тестовый аккаунт из `VK_ALLOWED_USER_IDS`, iPhone и Android (и веб-версия ВКонтакте).

1. Написать сообществу «Начать». Короткое приветствие с предупреждением, что
   переписку видят администраторы сообщества ВКонтакте. Под ним: «Открыть приложение»
   (на всю ширину), ниже «Мои записи» и «Администратор». Других кнопок нет.
2. «Открыть приложение» — открывается Mini App клиники (не браузер со ссылкой).
   Записаться на свободное время, закрыть приложение.
3. «Мои записи» — та же запись и подсказка про перенос в приложении.
4. Текстом: «Хочу записаться к терапевту», «Какие врачи есть?», «Сколько стоит
   приём?», «Где находится клиника?», «Перенеси мою запись» — ответы по сути.
5. «Администратор» → бот просит написать, что передать → написать «Хочу перенести
   запись на пятницу после 16:00» → предпросмотр с этим текстом дословно.
6. «Не разрешаю» → бот подтверждает, что ничего не передано, и предлагает позвать
   администратора без описания. В панели «Обращения» — пусто.
7. Повторить шаг 5 → «Разрешаю передачу» → бот называет номер обращения. Администратору
   ВКонтакте пришло уведомление со ссылкой и номером, **без текста**. Повторное нажатие
   «Разрешаю передачу» — «кнопка устарела», второго обращения нет.
8. Панель под ролью «Администратор» → «Обращения» → «Открыть текст» — ровно текст из
   предпросмотра; других сообщений переписки нет. «Обработано».
9. Под владельцем и врачом — раздела «Обращения» нет; `/api/admin/requests` → 403.
   У владельца в «Журнале доступа» — запись об открытии без текста.
10. В боте (он молчит, пока отвечает администратор) нажать «Отозвать передачу №…» или
    написать «отозвать передачу» → бот подтверждает; в панели текст больше не открывается.
11. «бот» или «Вернуться к боту» — бот снова отвечает.

## 9. Откат

1. Код: `git checkout <точка отката из раздела 2> && npm ci &&
NODE_OPTIONS=--max-old-space-size=1024 npm run build`, перезапустить бота и панель.
   Старая версия работает с базой v7: новые таблицы ей не мешают, записи и сотрудники
   сохраняются. Обращения остаются в базе (зашифрованы), но старая панель их не
   показывает; истёкшие удалит новая версия после возврата.
2. Если откат ниже `c199a0c` (на `a27d677`) — сначала раздел 7 `privacy-update-vps.md`
   (отключить учётные записи врачей и администраторов: в старой версии ролей нет).
3. Восстанавливать базу из копии — только при повреждении (пропадут записи после копии):
   остановить бота и панель, `cp -p ../bot-backups/bot-<дата>.sqlite .data/bot.sqlite`,
   `rm -f .data/bot.sqlite-wal .data/bot.sqlite-shm`.

## 10. Чего не делать

- Не менять `MEDICAL_DATA_KEY` и не выводить его значение.
- Не выдавать роль «Администратор» тем, кому пациенты не давали согласия.
- Не говорить пациентам, что отказ от передачи скрывает переписку: её видят
  руководители сообщества ВКонтакте.
- Не включать `BOT_MEDICAL_QUESTIONS` иначе, чем решил владелец.
