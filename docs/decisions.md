# Журнал архитектурных решений

Коротко: решение, причина, отклонённые варианты, оставшиеся ограничения. Новые решения
добавляются в конец со следующим номером; отменённые не удаляются, а помечаются
«заменено Р-NN». Подробности — в документах по ссылкам.

## Р-01. Одно приложение Next.js для сайта и админ-панели

- **Решение:** Next.js 16 (App Router) + TypeScript; панель — маршруты `/admin` и
  `/api/admin` в том же приложении, публичный сайт — группа `src/app/(site)`.
- **Почему:** один стек, одна сборка и CI, меньше инфраструктуры на VPS с 2 ГБ RAM.
- **Отклонено:** отдельный бэкенд или отдельное приложение панели.
- **Ограничения:** сборка тяжёлая для VPS (нужен swap и ограничение кучи).

## Р-02. VK-бот — Bots Long Poll, ядро не знает о канале и LLM

- **Решение:** канал `src/bot/vk/` через Long Poll; ядро `createBot().handle()`; LLM —
  интерфейс `ConversationModel`, расписание — `ScheduleProvider`.
- **Почему:** не нужен публичный адрес и https для приёма событий; ядро тестируется без
  ВКонтакте и OpenAI; канал или МИС можно заменить.
- **Отклонено:** Callback API (нужен внешний адрес, сложнее проверка запросов).
- **Ограничения:** бот работает, пока запущен процесс.

## Р-03. GPT ведёт разговор, но решения проверяются программой

- **Решение:** OpenAI Responses API через `fetch`, Structured Outputs, действия из
  `MODEL_ACTIONS`; правила безопасности и фильтр темы — до модели; запись и отмена —
  только подтверждением пациента; без ключа или при ошибке — правила.
- **Почему:** модель не должна ставить диагнозы, называть время и цены или записывать
  сама; бот должен работать без OpenAI и экономить запросы.
- **Отклонено:** SDK (лишняя зависимость), свободный ответ модели без схемы.
- **Ограничения:** текст сообщений (без телефонов и почты) уходит в OpenAI — для
  реальных пациентов нужна правовая оценка.

## Р-04. SQLite (`node:sqlite`) — общий источник данных бота и панели

- **Решение:** один файл `BOT_DB_PATH` в режиме WAL; справочники клиники в базе, а не в
  коде; миграции через `PRAGMA user_version`, только добавлением.
- **Почему:** без отдельного сервера БД; панель и бот видят одни данные; двойная запись
  исключена уникальным индексом даже при одновременных запросах двух процессов.
- **Отклонено:** отдельные хранилища для панели, копии справочников, внешняя СУБД
  на текущем этапе.
- **Ограничения:** `node:sqlite` — экспериментальный модуль Node.js 24 (предупреждение в
  журнале); один сервер.

## Р-05. Роли сотрудников и проверка прав на сервере

- **Решение:** роли `owner` / `admin` / `doctor`; одна таблица прав
  (`src/admin/permissions.ts`), каждый маршрут API — в `ROUTES`, каждая страница —
  `requirePage`. Существующие учётные записи при миграции v6 стали `owner`.
- **Почему:** скрытие интерфейса не защищает от прямых запросов; минимальные права.
- **Отклонено:** проверки только в интерфейсе; медицинский доступ по роли.
- **Ограничения:** владелец задаёт привязку «учётная запись ↔ врач» и технически может
  выдать себе доступ врача; видно только по журналам.

## Р-06. Врач видит описание жалобы только по согласию пациента на конкретную запись

- **Решение:** согласие создаётся только действием пациента в боте (предпросмотр →
  «Передать врачу»), на одну запись и одного врача, с целью и сроком; отзыв, отмена,
  перенос и срок удаляют содержимое; каждая попытка доступа — в журнале.
- **Почему:** VK ID не доказывает личность; роль врача сама по себе не должна открывать
  историю бота; никаких автоматических разрешений.
- **Отклонено:** доступ врача ко всей переписке; доступ по роли без связи с записью.
- **Ограничения:** сведения — со слов собеседника, личность не подтверждена.

## Р-07. Шифрование медицинских сведений в базе ключом вне базы

- **Решение:** `MEDICAL_DATA_KEY` (AES-256-GCM, контекст строки) для `sessions.state` и
  согласий; без ключа передача врачу выключена.
- **Почему:** копии и выгрузки базы без ключа не раскрывают сведения.
- **Ограничения:** не защищает от администратора сервера, у которого есть и база, и ключ.

## Р-08. ВКонтакте остаётся основным каналом; перенос медицинского чата отклонён

- **Решение (владелец проекта, после этапа 2):** ВКонтакте — основной канал общения
  пациента с ботом. Перенос медицинской части разговора на отдельный сайт клиники
  **сейчас отклонён**.
- **Почему:** решение владельца; пациенты клиники общаются во ВКонтакте.
- **Отклонённая альтернатива:** одноразовая ссылка на защищённую форму на домене
  клиники (описана в `docs/medical-privacy.md`, раздел 1) — единственное известное
  техническое решение проблемы Р-09; к ней можно вернуться отдельным решением.
- **Что делается вместо:** честные предупреждения в боте, режим
  `BOT_MEDICAL_QUESTIONS=false`, минимум руководителей сообщества.

## Р-09. Администраторы сообщества ВКонтакте видят переписку — нерешённое ограничение

- **Факт:** руководители сообщества с доступом к сообщениям потенциально видят всю
  переписку пациента с ботом, включая сведения о самочувствии. Роли панели, согласия и
  шифрование базы этого не ограничивают. Вживую из облака не проверялось (VK недоступен),
  считается верным, пока не доказано обратное.
- **Правило:** нельзя заявлять — в боте, панели, документах, отчётах, — что медицинская
  переписка скрыта от администраторов ВКонтакте, пока это технически не обеспечено.
- **Статус:** не решено (см. Р-08). Для реальных пациентов — блокирующее ограничение.

## Р-10. Согласие на передачу фрагмента переписки администратору (реализовано, см. Р-15)

- **Решение:** согласие пациента на передачу **конкретного фрагмента** конкретному
  получателю с целью, сроком, отказом без раскрытия, отзывом и журналом. Реализовано
  этапами 3 и 5 отдельной таблицей `patient_requests` (Р-15); `disclosure_consents` с
  получателем `admin` не используется.
- **Ограничение:** такое согласие регулирует только доступ через нашу панель и **не
  является защитой от доступа через сам ВКонтакте** (Р-09). Описывать его так нельзя.

## Р-11. Память проекта — лёгкие документы, без RAG

- **Решение:** компактная память в Markdown (`project-memory.md`, `architecture.md`,
  `decisions.md`, `current-status.md`), правила по областям в `docs/rules/`, поиск по
  репозиторию вместо чтения всего подряд.
- **Почему:** проект небольшой, документы и код хорошо ищутся `grep`; RAG, векторная
  база или MCP-сервер добавили бы зависимости и инфраструктуру без доказанной пользы.
- **Вернуться, если:** память перестаёт помещаться в ~150 строк, поиск регулярно не
  находит нужное или документации станет на порядок больше.

## Р-12. VK Mini App — маршруты существующего Next.js над общей базой

- **Решение:** `/miniapp` и `/api/miniapp` в том же приложении и процессе, что панель;
  запись через `ClinicSchedule` и `SqliteStore` бота (источник `miniapp`); новых таблиц
  и миграций нет.
- **Почему:** одна система бронирования для бота, панели и Mini App; без нового сервера
  на VPS с 2 ГБ RAM; синхронизация без копирования данных.
- **Отклонено:** отдельный сервер или SPA с собственным бэкендом; отдельная система
  записи.
- **Ограничения:** публичный сайт по-прежнему закрыт — nginx открывает только
  `/miniapp` и `/api/miniapp`.

## Р-13. Авторизация Mini App — подпись параметров запуска в каждом запросе

- **Решение:** клиент передаёт строку параметров запуска в заголовке
  `X-VK-Launch-Params`, сервер проверяет HMAC-SHA256 защищённым ключом (официальный
  алгоритм VK), приложение и срок `vk_ts`; пациент — только `vk_user_id` из подписи.
  Доступ — список тестовых аккаунтов.
- **Почему:** без собственных сессий и cookie (в iframe ВКонтакте сторонние cookie
  могут блокироваться); подделка запроса с чужого сайта невозможна.
- **Отклонено:** VK ID из клиента без подписи; обмен на cookie-сессию; демонстрационный
  обход авторизации.
- **Ограничения:** подписанная строка действует до `MINIAPP_LAUNCH_MAX_AGE_HOURS` — её
  нельзя писать в журналы (в nginx `access_log off` для Mini App).

## Р-14. Меню VK-бота — три действия, главное — VK Mini App

- **Решение (этап 3):** «Открыть приложение» (кнопка `open_app` Mini App 54834865 в
  контексте сообщества), «Мои записи», «Администратор». Пояснение «врачи, цены и запись»
  — в тексте над кнопками. Справка, запись и перенос — свободным текстом с ИИ.
- **Почему:** меню было перегружено и дублировало приложение; у кнопок ВКонтакте только
  подпись до 40 символов, у `open_app` нет цвета — составную кнопку сделать нельзя.
- **Отклонено:** обычная ссылка на `/miniapp` (не открывает приложение в контексте
  сообщества); отдельная кнопка «Записаться онлайн» рядом с записью через бота (заменена,
  коммит `cf28822`).
- **Ограничения:** клиенты без `open_app` в `button_actions` получают «Записаться на
  приём» (запись через бота); вид кнопок на iPhone и Android не проверен из облака.

## Р-15. Обращение к администратору — дословный текст пациента с явным согласием

- **Решение (этап 5):** текст обращения — только слова пациента (контакты убираются, это
  видно); предпросмотр; согласие — кнопка с меткой SHA-256 показанного текста; хранение
  — зашифрованно, с хэшем и версией согласия, неизменяемо (триггеры), до 30 дней (7 после
  «обработано»); отзыв удаляет текст; раздел «Обращения» — только роль `admin`; журнал
  доступа без содержания.
- **Почему:** резюме от модели могло бы добавить факты, которых пациент не писал;
  дословный текст ничего не выдумывает и проверяем пациентом.
- **Отклонено:** передача всей переписки или истории бота; резюме модели; автоматическое
  согласие; доступ владельца и врачей к тексту обращений.
- **Ограничения:** не защищает от чтения переписки в интерфейсе ВКонтакте (Р-09);
  прочитанное сотрудником отозвать нельзя; без `MEDICAL_DATA_KEY` функция выключена.

## Р-16. Дизайн Mini App — «премиальная частная клиника», без выдуманных данных

- **Решение (этап «редизайн»):** тёплый белый фон, глубокий изумрудный акцент, белые
  карточки с мягкими тенями, серифные заголовки (Lora, самохостинг через `next/font`),
  крупные кнопки; токены и утилиты — в `globals.css`, компоненты — `src/components/miniapp/`.
  Новые экраны — карточка врача и единая форма записи; бизнес-логика и API прежние (в
  ответ клиники добавлен только `specialtyId` услуги).
- **Почему:** демонстрация клиникам; референс владельца — вариант A.
- **Отклонено:** стаж, рейтинги, отзывы, «причина визита» и личные данные в форме
  записи (этого нет в базе или не собирается), фото реальных людей у вымышленных врачей,
  преимущества-обещания о клинике («опытные врачи», «современное оборудование»).
- **Ограничения:** без фотографий — монограммы и иллюстрация; список изображений —
  `vk-mini-app-deploy.md`, раздел 9.
