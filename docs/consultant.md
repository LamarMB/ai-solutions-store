# Консультант: архитектура и подключение LLM

## Сейчас — демонстрационный помощник

`/consultant` работает с `MockChatProvider` — это **правила, а не ИИ**: ключевые слова
задач и отраслей сопоставляются с решениями каталога. Интерфейс прямо это сообщает
(плашка «Демонстрационный помощник, а не ИИ»). Внешние API не вызываются, переписка не
сохраняется (живёт только в состоянии страницы) и не логируется.

## Как устроено

| Часть                                                                                 | Файл                                |
| ------------------------------------------------------------------------------------- | ----------------------------------- |
| Интерфейс `ChatProvider`, проверка истории (Zod)                                      | `src/consultant/types.ts`           |
| Mock-провайдер (правила, примеры задач)                                               | `src/consultant/mock-provider.ts`   |
| Выбор провайдера                                                                      | `src/consultant/provider.ts`        |
| Обработка: проверка → частота → скрытие контактов → провайдер → проверка рекомендаций | `src/consultant/service.ts`         |
| Скрытие email и телефонов                                                             | `src/consultant/privacy.ts`         |
| Карточки рекомендаций из каталога                                                     | `src/consultant/recommendations.ts` |
| Server Action                                                                         | `src/app/consultant/actions.ts`     |
| Интерфейс чата                                                                        | `src/components/consultant/`        |

Гарантии не зависят от провайдера:

- провайдер возвращает только `solutionId` и причину; карточки (название, пакеты, цены)
  собираются **из каталога** — выдуманные решения и цены отбрасываются;
- email и телефоны в сообщениях заменяются до передачи провайдеру;
- история ограничена (30 сообщений, 1000 символов на сообщение пользователя), таймаут
  ответа 15 с, частота — 30 сообщений в минуту на клиента.

## Подключение LLM (отдельным решением)

1. Выбрать провайдера после проверки доступности, стоимости, условий обработки данных и
   хранения переписки на его стороне.
2. Реализовать `ChatProvider` (например, `LlmChatProvider`): системный промпт с данными
   каталога (id, названия, описания, ограничения), требование отвечать только по
   каталогу и возвращать структурированный ответ `{ text, recommendations, followUps }`.
3. Ключ API — только в переменных окружения, выбор провайдера в `getChatProvider()`.
4. Обновить тексты интерфейса (сейчас: «не ИИ») и политику конфиденциальности —
   переписка будет уходить внешнему сервису.
5. Прогнать тесты `src/consultant/` на новом провайдере: рекомендации вне каталога всё
   равно отфильтруются, но качество ответов нужно проверить отдельно.
