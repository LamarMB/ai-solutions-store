# VK Mini App клиники: настройка и обновление VPS

Инструкция для того, кто обслуживает VPS (например, Claude Desktop). Пути, домен, имена
сервисов, ID приложения и ключи здесь не выдумываются — подставьте свои вместо `<…>`.
Секреты в чат, Git и журналы не попадают. **Приложение не опубликовано** и не
проверялось внутри ВКонтакте: из облачного окружения разработки ВКонтакте недоступен.

## 1. Что это

- `https://<домен>/miniapp` — мобильное приложение «Демо-Мед» внутри ВКонтакте: врачи,
  свободное время, запись, «Мои записи» (отмена и перенос), услуги, о клинике.
- API — `https://<домен>/api/miniapp/*`. Каждый запрос несёт подписанные ВКонтакте
  параметры запуска; сервер проверяет подпись защищённым ключом приложения, пациент —
  `vk_user_id` из проверенной строки. Без подписи (страница открыта вне ВКонтакте) —
  только пояснение «Откройте приложение во ВКонтакте».
- Та же база SQLite (`BOT_DB_PATH`) и то же расписание, что у бота и панели: запись из
  Mini App сразу видна в панели (источник «VK Mini App») и в боте («Мои записи»), занятое
  где угодно время не предлагается. Отдельного процесса нет — это маршруты того же
  Next.js, что и панель (`next start`).
- Медицинский диалог остаётся в сообщениях сообщества (решение владельца, `decisions.md`,
  Р-08). Mini App не показывает жалобы, историю разговора и пометки администратора.
  Переписку в сообщениях сообщества по-прежнему видят руководители сообщества
  ВКонтакте — это ограничение не решено (`medical-privacy.md`, раздел 1).
- Доступ — только тестовым аккаунтам (`MINIAPP_ALLOWED_USER_IDS`, по умолчанию — те
  же, что `VK_ALLOWED_USER_IDS` у бота). Остальные видят «Доступ только для тестовых
  аккаунтов».

## 2. Что сделать владельцу во ВКонтакте

Названия разделов сверить с dev.vk.com — интерфейс ВКонтакте меняется, отсюда он не
проверялся.

1. Создать приложение типа **VK Mini Apps** (dev.vk.com → «Мои приложения» → создать).
   Записать **ID приложения** и **Защищённый ключ** (раздел настроек приложения).
   Ключ — секрет: только в `.env.local` на сервере.
2. В настройках приложения указать адрес для мобильной версии, мобильного веба и
   десктопа: `https://<домен>/miniapp` (только https, без параметров).
3. Пока приложение не прошло модерацию, оно открывается только администраторам
   приложения и тестировщикам — добавить туда тестовые аккаунты.
4. Привязать приложение к сообществу клиники (ID 242364009): «Управление сообществом →
   Приложения» (или кнопка в меню сообщества). Публикация в каталоге и модерация —
   отдельное решение владельца.
5. Публичный запуск для реальных пациентов не делать: данные клиники вымышленные,
   правовая оценка персональных данных не проведена.

## 3. Переменные окружения

В `.env.local` проекта (его читает Next.js):

| Переменная                     | Обязательна | Значение                                                                                              |
| ------------------------------ | ----------- | ----------------------------------------------------------------------------------------------------- |
| `VK_MINIAPP_ID`                | да          | ID приложения VK Mini Apps (число)                                                                    |
| `VK_MINIAPP_SECRET`            | да          | защищённый ключ приложения — для проверки подписи; без него API отвечает 503                          |
| `MINIAPP_ALLOWED_USER_IDS`     | нет         | VK ID с доступом через запятую; пусто — берётся `VK_ALLOWED_USER_IDS`; оба пусты — доступ закрыт всем |
| `MINIAPP_LAUNCH_MAX_AGE_HOURS` | нет         | сколько часов действуют параметры запуска (по умолчанию 24)                                           |
| `VK_GROUP_ID`                  | нет         | уже есть у бота; нужен для кнопки «Написать в сообщения сообщества»                                   |
| `BOT_DB_PATH`                  | нет         | та же база, что у бота и панели                                                                       |

Токен сообщества и ключ OpenAI Mini App не использует и не получает.

### Кнопка «Записаться онлайн» в боте

Если `VK_MINIAPP_ID` задан, бот читает его тоже (перезапуск бота обязателен) и там, где
предлагает «Записаться на приём» (главное меню, «Мои записи» без записей, после записи),
добавляет отдельным рядом кнопку ВКонтакте типа `open_app` «📅 Записаться онлайн» — она
открывает Mini App поверх чата в контексте сообщества (`owner_id = -VK_GROUP_ID`).
Постоянной кнопки у поля ввода, как у ботов Telegram, во ВКонтакте нет.

- Кнопка показывается, только если клиент сообщает `open_app` в `button_actions` и
  inline-клавиатура не выходит за 6 рядов и 10 кнопок; иначе меню прежнее.
- Если ВКонтакте отклонит клавиатуру с кнопкой (ошибки 911–913), то же сообщение
  уходит без неё, в журнал — `open_app keyboard rejected: vk <код>`.
- В строке запуска бота — `кнопка Mini App: да`.
- Код: `src/bot/vk/keyboard.ts` (`MiniAppButton`), `src/bot/vk/runner.ts`, тесты —
  `keyboard.test.ts`, `runner.test.ts`.

## 4. Ресурсы VPS (2 ГБ RAM)

Новых процессов нет: Mini App — часть `next start` панели (~150–250 МБ). Сборка — как
раньше, самый тяжёлый шаг: `NODE_OPTIONS=--max-old-space-size=1024 npm run build`, swap
обязателен (`admin-panel-deploy.md`, раздел 4). Новая зависимость одна —
`@vkontakte/vk-bridge` (официальный VK Bridge, только в браузере).

## 5. Обновление VPS

На VPS сейчас `a27d677` (схема v5); этап 2 (`c199a0c`, роли и согласия, схема v6) туда
ещё не ставился. Это обновление включает и его: выполнить сначала шаги
`privacy-update-vps.md` (включая ключ `MEDICAL_DATA_KEY` и проверку ролей), используя
текущую версию ветки, затем шаги ниже. Новых миграций Mini App не добавляет — схема
остаётся v6.

1. Состояние и точка отката:
   ```bash
   git status --short            # локальные изменения не затирать
   git rev-parse HEAD            # запомнить для отката
   ```
2. **Резервная копия базы** (без остановки бота):
   ```bash
   npm run db:backup             # → ../bot-backups/bot-<дата>.sqlite
   ```
3. Код, зависимости, проверки, сборка:
   ```bash
   git fetch origin claude/jolly-bohr-j26x8f
   git checkout claude/jolly-bohr-j26x8f
   git pull --ff-only origin claude/jolly-bohr-j26x8f
   npm ci
   npx vitest run src/bot src/admin src/miniapp
   NODE_OPTIONS=--max-old-space-size=1024 npm run build
   ```

4. Переменные из раздела 3 — в `.env.local` (`chmod 600 .env.local`). Значения не
   выводить в терминал чата.
5. Перезапуск бота и панели тем же способом, каким они запущены. Без `VK_MINIAPP_ID` и
   `VK_MINIAPP_SECRET` панель работает, а `/api/miniapp/*` отвечает 503 (в журнале —
   `[miniapp] не настроено`, без значений).

## 6. nginx и HTTPS

ВКонтакте открывает только https. В существующий `server` панели добавить Mini App,
**не открывая публичный сайт** (`location /` остаётся `return 404`):

```nginx
location ~ ^/(miniapp|api/miniapp)(/|$) {
  # Параметры запуска (VK ID и подпись) приходят в адресе /miniapp?… —
  # не записываем их в журнал доступа.
  access_log off;
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-Host "";
}
```

- Если для `/admin` настроено ограничение по IP (`allow`/`deny`), на Mini App его не
  распространять: пациенты открывают приложение с любых адресов.
- Встраивание: Next.js отдаёт для `/miniapp` `Content-Security-Policy: frame-ancestors
https://vk.com https://*.vk.com https://vk.ru https://*.vk.ru`, для всех остальных
  страниц — `X-Frame-Options: DENY`. nginx не должен добавлять свой `X-Frame-Options`
  для `/miniapp` (иначе веб-версия ВКонтакте не покажет приложение).
- `nginx -t && sudo systemctl reload nginx`.

## 7. Проверка

С сервера (без ВКонтакте):

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<домен>/miniapp               # 200
curl -s -w "\n%{http_code}\n" https://<домен>/api/miniapp/clinic                # 401 «Откройте приложение во ВКонтакте»
curl -s -D - -o /dev/null https://<домен>/miniapp | grep -i frame-ancestors     # список доменов VK
curl -s -D - -o /dev/null https://<домен>/admin/login | grep -i x-frame        # DENY
curl -s -o /dev/null -w "%{http_code}\n" https://<домен>/                       # 404 (сайт закрыт)
```

`https://<домен>/miniapp` в обычном браузере — экран «Откройте приложение во
ВКонтакте». Добавление `?vk_user_id=…` вручную — «Не удалось подтвердить вход».

Внутри ВКонтакте (телефон с тестовым аккаунтом, Android и iOS, плюс веб-версия):

1. Открыть приложение из сообщества — загрузка без вечного индикатора (VKWebAppInit).
2. «Врачи» → фильтр по специальности → «Записаться» → дата → время → «Подтвердить
   запись» → экран «Вы записаны».
3. Панель → «Записи»: та же запись, источник «VK Mini App».
4. Бот в сообщениях сообщества → «Мои записи»: та же запись. И наоборот: записаться
   через бота — запись видна в «Записи» Mini App.
5. Панель → занять слот вручную → Mini App его не предлагает. Отключить врача — исчез.
   Изменить цену — новая цена в Mini App.
6. «Записи» → «Отменить» → подтверждение → слот снова свободен в боте и панели.
7. «Перенести» → новое время → в панели запись перенесена.
8. Системная кнопка «Назад» на Android закрывает экран записи, не закрывая приложение.
9. Аккаунт не из `MINIAPP_ALLOWED_USER_IDS` — «Доступ только для тестовых аккаунтов».
10. Приложение открыто дольше `MINIAPP_LAUNCH_MAX_AGE_HOURS` — «Сеанс устарел»;
    перезапуск приложения возвращает доступ.

## 8. Откат без потери записей

Mini App не меняет схему базы, записи из него — обычные строки `bookings` с
`source = 'miniapp'`.

1. Код: `git checkout <запомненный коммит> && npm ci &&
NODE_OPTIONS=--max-old-space-size=1024 npm run build`, перезапустить бота и панель.
   Записи, сделанные через Mini App, остаются и видны в панели и боте (в старой панели
   источник может отображаться пустым — это только подпись).
2. nginx: убрать `location` Mini App, `nginx -t && sudo systemctl reload nginx`.
3. При откате дальше этапа 2 — также раздел 7 `privacy-update-vps.md` (отключить
   учётные записи врачей и администраторов до отката).
4. Базу из копии восстанавливать только при повреждении (пропадут записи после копии):
   остановить бота и панель, затем
   ```bash
   cp -p ../bot-backups/bot-<дата>.sqlite .data/bot.sqlite
   rm -f .data/bot.sqlite-wal .data/bot.sqlite-shm
   ```

## 9. Безопасность — кратко

- Подпись: HMAC-SHA256 параметров `vk_*` защищённым ключом (алгоритм и тестовый пример
  — официальный VKCOM/vk-apps-launch-params, проверено тестом). Повтор параметра,
  чужое приложение, устаревший `vk_ts` — отказ.
- VK ID из тела запроса, адреса или отдельных заголовков не принимается; чужая и
  несуществующая запись — одинаковый ответ 404.
- Cookie не используются; без подписи запрос не проходит, CORS не разрешён —
  подделка запроса с чужого сайта не работает. Подписанные параметры действуют
  `MINIAPP_LAUNCH_MAX_AGE_HOURS`: кто получит строку запуска пациента (например, из
  журнала), сможет действовать от его имени до истечения срока — поэтому `access_log
off` в nginx.
- Повторы: двойное нажатие и повтор после обрыва сети возвращают ту же запись;
  повторная отмена — тот же результат. Ограничение частоты: 120 запросов и 20
  изменений в минуту на пациента (в памяти процесса).
