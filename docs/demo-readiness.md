# Готовность «Демо-Мед» к живой демонстрации

Аудит ветки `claude/demo-audit` (от `claude/launch-audit`, `634c12c`), 26.10.2026.
Проверено локально: временная база SQLite, вымышленные клиника, сотрудники и VK ID.
Продакшен, VPS, рабочая база и действующий бот не затрагивались.

## Как связаны компоненты

- **Одна база SQLite** (`BOT_DB_PATH`): бот, панель и Mini App — разные процессы с
  отдельными подключениями к одному файлу (режим WAL). Синхронизации и копий нет:
  все читают и пишут одни таблицы.
- **Расписание** — один класс `ClinicSchedule` у всех трёх. Двойную запись исключает
  уникальный индекс базы по активному слоту, а не проверка в коде.
- **Справочники** (врачи, часы, исключения, цены) — в базе; бот и Mini App видят
  изменения панели сразу (кэш сбрасывается по `PRAGMA data_version`).
- **Бот**: правила безопасности → фильтр темы → GPT (если задан ключ) → правила как
  запасной режим. Запись — только кнопкой «Подтвердить» / «да».
- **Mini App**: пациент — только `vk_user_id` из подписанных параметров запуска.
- **Панель**: роли `owner` / `admin` / `doctor`, права — `src/admin/permissions.ts`.

## Как проверено

- Сквозной тест `src/e2e/demo-scenarios.test.ts`: бот (правила), API Mini App и API
  панели на одной базе — 12 сценариев и проблемные ситуации (14 тестов).
- Гонка: 8 отдельных процессов одновременно записывали на 5 одинаковых слотов — в
  базе ровно по одной записи на слот, ошибок блокировки нет.
- Браузер (Chromium, 1280 и 390 px) на сервере `next start` с временной базой:
  - вход в панель — неверный пароль, cookie `__Host-`, HttpOnly, SameSite=Strict;
  - записи — создание, перенос, отмена, пометка с телефоном отклоняется;
  - расписание; роли врача и владельца; «Обращения»;
  - Mini App с локально подписанными параметрами — запись, двойное нажатие,
    перенос, отмена без сети, чужой аккаунт;
  - панель на телефоне — без горизонтальной прокрутки.
- Симулятор бота (`npm run bot:sim`) как отдельный процесс на той же базе: запись,
  «Мои записи», обращение с согласием — сразу видны в панели и Mini App.
- Клиентский код (`.next/static`) — без ключей и их значений.

**Не проверено (нужен владелец):**

- канал ВКонтакте: Long Poll, кнопки, `open_app`, уведомление администратору;
- Mini App внутри клиента ВКонтакте с настоящим ключом;
- режим GPT: из облачного окружения `api.vk.com` и `api.openai.com` недоступны.

## Найденные проблемы

**Важные**

1. **Исправлено (ветка `claude/privacy-notice`).** Предупреждение о том, что переписку
   видят руководители сообщества, было только в приветствии («Начать», «Здравствуйте»).
   Теперь оно в первом ответе каждого нового разговора, даже если пациент сразу пишет
   вопрос или жалобу, и не повторяется перед каждым сообщением.
2. **Исправлено.** Панель позволяла отметить «Приём состоялся» для будущей записи:
   запись пропадала из «Моих записей» пациента в боте, отменить её он не мог.
   Теперь сервер отклоняет отметку до начала приёма, кнопка у будущих записей скрыта.

**Низкие**

3. **Исправлено.** `npm run bot:sim` не учитывал `MEDICAL_DATA_KEY` и `VK_MINIAPP_ID`
   и вёл себя иначе, чем бот ВКонтакте (старая передача администратору без согласия).
4. Пометка записи с одним ФИО («Иванов Иван Петрович») принимается: фильтр ловит
   телефоны, почту и медицинские слова, но не имена. Подсказка в форме предупреждает.
5. Без `MEDICAL_DATA_KEY` бот использует старую передачу («Позвать администратора?
   Да/Нет»); если пациент вместо ответа пишет текст, бот разбирает его как новый
   запрос (может начать запись). С ключом, как на сервере, этого нет.
6. Справочники отбрасывают прошедшие исключения по системным часам, а не по часам
   расписания — влияет только на тесты со смещённым временем.

## Что нельзя обещать клиенту

- Синхронизацию с МИС и другими системами расписания — оценивается отдельно.
- Напоминания пациентам о приёме — их нет.
- Перенос записи в чате бота — только в приложении и панели.
- Скрытость переписки: её видят руководители сообщества ВКонтакте.
- Работу с реальными пациентами — до правовой оценки, политики и согласий.
- Другие каналы (сайт, Telegram, WhatsApp) — в планах.
- Постоянную работу GPT: при недоступности OpenAI бот продолжает по правилам, но
  отвечает проще.

## Сценарий живой демонстрации (5–7 минут)

Подготовка (до встречи):

- на сервере бот запущен — на главной панели «Бот ВКонтакте работает»;
- телефон с тестовым аккаунтом из `VK_ALLOWED_USER_IDS`;
- ноутбук с панелью под учётной записью с ролью **admin** — «Обращения» видит
  только она;
- накануне — пробный прогон и отмена тестовых записей.

1. **0:00–0:45 — знакомство.** На телефоне откройте сообщения сообщества и нажмите
   «Начать». Покажите приветствие: «Диагнозы не ставлю», честное предупреждение о
   видимости переписки, три кнопки меню.
2. **0:45–1:30 — вопросы.** «Сколько стоит приём терапевта?», «Где вы находитесь?» —
   ответы из справочника. Скажите, что цены и врачи меняются в панели.
3. **1:30–2:45 — запись в чате.** «Хочу записаться к терапевту» → врач → день → время
   → «Подтвердить». На ноутбуке — «Записи»: новая запись с источником ВКонтакте.
4. **2:45–3:45 — приложение.** «Открыть приложение» → «Записи» → «Перенести» → новое
   время. В панели — новое время, старое освободилось.
5. **3:45–4:30 — расписание.** В панели «Расписание» → выходной у врача на завтра. В
   приложении этот день пропал. Затем удалите исключение.
6. **4:30–5:30 — администратор.** В боте «Администратор» → вопрос («можно ли прийти с
   ребёнком») → предпросмотр → «Разрешаю передачу». В панели «Обращения» — только этот
   текст. Скажите честно: согласие регулирует только панель, а сам диалог во ВКонтакте
   администратор и другие руководители сообщества видят целиком — бот об этом
   предупреждает. Не говорите «администратор видит только этот текст».
7. **5:30–6:15 — безопасность.** «Сильная боль в груди, тяжело дышать» — сразу 103 и
   112, без записи. «Что выпить от головной боли?» — отказ без лекарств. После этого
   напишите «сброс».
8. **6:15–7:00 — итог.** Отмените запись в боте («Мои записи») — время снова свободно.
   Назовите честно, что демо и что требует внедрения (раздел выше).
