# Админ-панель клиники: развёртывание на существующем VPS

Инструкция для того, кто обслуживает VPS с работающим VK-ботом (например, Claude Desktop).
Сервер, пути и имена сервисов здесь не выдумываются — подставьте свои значения
вместо `<…>`. Пароли, токены и ключи в документ не вносятся.

Ветка: `claude/jolly-bohr-j26x8f`. Версия бота до панели — коммит `e6018b4`.

> **Обновление уже работающей панели (a27d677) до ролей и медицинской
> конфиденциальности — `docs/privacy-update-vps.md`.** Роли и что видит каждая —
> `docs/medical-privacy.md`.

## 1. Что это и как связано с ботом

- Панель — часть Next.js-приложения репозитория: страницы `/admin/*` и API
  `/api/admin/*`. Отдельной системы записей нет.
- **Один источник данных — файл SQLite бота** (`BOT_DB_PATH`, по умолчанию
  `.data/bot.sqlite`). Бот (`npm run bot:vk`) и панель (`next start`) — разные
  процессы с одной базой в режиме WAL.
- Врачи, специальности, часы приёма, выходные, цены и настройки клиники теперь
  хранятся в базе, а не в коде. Бот читает их при каждом сообщении (с кэшем до первого
  изменения базы), поэтому изменения из панели действуют без перезапуска бота.
- Запись из панели и запись через бота идут через одну логику (`ClinicSchedule`);
  двойную запись исключает уникальный индекс базы, даже при одновременных запросах.

| Раздел     | Возможности                                                                                |
| ---------- | ------------------------------------------------------------------------------------------ |
| Главная    | записи на сегодня, неделя, ближайшие приёмы, обращения в бот за 7 дней, статус бота        |
| Записи     | список, фильтры и поиск, детали, ручная запись, перенос, «приём состоялся», отмена         |
| Врачи      | добавление, правка, стоимость приёма, включение/отключение, удаление с защитой записей     |
| Расписание | часы по дням недели, длительность приёма, выходные и перерывы, просмотр свободного времени |
| Настройки  | название, адрес, телефон, режим работы, описание, как добраться, памятка, услуги и цены    |

Разделы зависят от роли (`owner` / `admin` / `doctor`), права проверяет сервер —
таблица в `docs/medical-privacy.md`. Владельцу доступны также «Сотрудники» и «Журнал
доступа», врачу — только «Мои приёмы».

## 2. Миграции базы (автоматически)

При первом запуске новой версии бота **или** панели база переходит до версии 6
(`PRAGMA user_version`), каждая миграция — в транзакции и один раз:

- **v4** — таблицы справочников (`clinic_settings`, `specialties`, `doctors`,
  `doctor_hours`, `services`, `schedule_exceptions`) с начальными данными прежней
  вымышленной клиники из кода (id врачей те же — старые записи остаются валидными);
  у `bookings` появляются `status` (confirmed / completed / cancelled), `source`
  (vk / admin), `note`, `updated_at`, `completed_at`; отменённые записи получают
  статус `cancelled`. Ни одна запись не удаляется.
- **v5** — `admin_users`, `admin_sessions` (только SHA-256 токена), `admin_audit`
  (журнал действий без персональных данных), `bot_status` (отметка «бот на связи»).
- **v6** — роли сотрудников (`role`, `doctor_id`; все существующие учётные записи
  становятся `owner`, пароли и сессии сохраняются), `staff_invites` (только хэш токена),
  `disclosure_consents` (согласия пациентов, содержимое зашифровано),
  `medical_access_log` (кто и когда открывал сведения, без содержания).

Миграции безопасны при одновременном запуске двух процессов (`BEGIN IMMEDIATE`).
Проверено тестом на копии базы версии 3 со старыми записями.

## 3. Переменные окружения

В `.env.local` проекта (его читают и бот, и Next.js):

| Переменная              | Обязательна | Значение                                                                                                                      |
| ----------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `BOT_DB_PATH`           | нет         | путь к базе бота; **у бота и панели должен совпадать** (по умолчанию `.data/bot.sqlite`, путь от каталога проекта)            |
| `ADMIN_COOKIE_SECURE`   | нет         | `true` по умолчанию: cookie `__Host-admin_session` только по https. `false` — только для локальной проверки по http           |
| `ADMIN_ALLOWED_ORIGINS` | нет         | дополнительные адреса панели через запятую, если она открывается не по тому хосту, что приходит в `Host`                      |
| `MEDICAL_DATA_KEY`      | нет         | ключ шифрования разговоров и согласий (32 байта base64), **один и тот же у бота и панели**; без него передача врачу выключена |

Остальные переменные бота не меняются.

## 4. Ресурсы: VPS с 2 ГБ RAM

- Работа: бот ~80–120 МБ, `next start` ~150–250 МБ — помещаются.
- **Сборка `next build` — самый тяжёлый шаг (до ~1–1,5 ГБ).** Перед сборкой проверьте
  память и подключите swap, если его нет:
  ```bash
  free -m
  swapon --show
  # если swap нет — однократно (2 ГБ):
  sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
  sudo mkswap /swapfile && sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  ```
- Собирайте с ограничением кучи: `NODE_OPTIONS=--max-old-space-size=1024 npm run build`.
  Бот во время сборки можно не останавливать.
- Если сборка всё равно падает по памяти — соберите на другой машине той же ветки
  (`npm ci && npm run build`) и перенесите каталог `.next` на сервер (rsync/scp),
  затем на сервере только `npm ci` и запуск.

## 5. Порядок безопасного обновления

Работайте под пользователем, от которого запущен бот, в каталоге проекта.

1. **Состояние.** `git status --short` — если есть локальные изменения, не затирайте
   их: остановитесь и разберитесь (`git stash` только осознанно). Запомните коммит для
   отката: `git rev-parse HEAD`.
2. **Резервная копия базы** — без остановки бота:
   ```bash
   npm run db:backup                 # → ../bot-backups/bot-<дата>.sqlite
   ```
   (на старой версии кода этой команды нет — тогда остановите бота и скопируйте
   `.data/bot.sqlite*` вручную, как в `docs/conversational-bot-deploy.md`).
3. **Код и зависимости:**
   ```bash
   git fetch origin claude/jolly-bohr-j26x8f
   git checkout claude/jolly-bohr-j26x8f
   git pull --ff-only origin claude/jolly-bohr-j26x8f
   node -v                           # 24.x
   npm ci
   ```
4. **Проверки** (не трогают рабочую базу):
   ```bash
   npx vitest run src/bot src/admin  # бот и панель, с мок-данными
   ```
5. **Сборка** — см. раздел 4: `NODE_OPTIONS=--max-old-space-size=1024 npm run build`.
6. **Перезапуск бота** — тем же способом, каким он запущен (`systemctl restart <сервис>`,
   `pm2 restart <имя>` …). Бот применит миграции v4–v5. В журнале: `схема v5`,
   `long poll: connected`. Пропуск событий на время перезапуска не страшен: Long Poll
   отдаёт накопившиеся события после переподключения.
7. **Первый сотрудник — владелец** (пароль вводится скрыто, не попадает в историю команд):
   ```bash
   npm run admin:user -- create <логин>      # первая учётная запись получает роль owner
   npm run admin:user -- list
   ```
   Пароль — не короче 10 символов, буквы и цифры. Демонстрационных учётных записей нет.
   Остальных сотрудников владелец приглашает в разделе «Сотрудники» (одноразовая ссылка,
   пароль задаёт сам сотрудник) или командой
   `npm run admin:user -- create <логин> --role=admin|doctor [--doctor=<id врача>]`.
8. **Запуск панели** как отдельного сервиса, только на localhost (наружу — через
   nginx с https). Пример systemd-юнита `/etc/systemd/system/clinic-admin.service`:
   ```ini
   [Unit]
   Description=Clinic admin panel (Next.js)
   After=network.target

   [Service]
   User=<пользователь бота>
   WorkingDirectory=<каталог проекта>
   Environment=NODE_ENV=production
   Environment=NODE_OPTIONS=--max-old-space-size=384
   ExecStart=/usr/bin/env npx next start -H 127.0.0.1 -p 3000
   Restart=on-failure
   RestartSec=5

   [Install]
   WantedBy=multi-user.target
   ```
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now clinic-admin
   curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/admin/login   # 200
   ```
   Если на сервере уже используется pm2 — `pm2 start "npx next start -H 127.0.0.1 -p 3000" --name clinic-admin`.
9. **nginx: наружу — только панель.** Публичный сайт не открывается без решения
   владельца, поэтому проксируются только `/admin`, `/api/admin` и статика Next.js:
   ```nginx
   server {
     listen 443 ssl http2;
     server_name <домен панели>;
     # ssl_certificate … (Let's Encrypt / certbot)
     add_header Strict-Transport-Security "max-age=31536000" always;

     location ~ ^/(admin|api/admin|_next)(/|$) {
       # Страница приглашения /admin/invite держит токен во фрагменте (#…) — он не
       # попадает в журнал nginx.
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_set_header X-Forwarded-Host "";
     }
     location / { return 404; }
   }
   ```
   `nginx -t && sudo systemctl reload nginx`. Без https cookie входа не установится
   (так задумано). Дополнительно можно ограничить доступ по IP (`allow`/`deny`).
10. **Проверка** — раздел 7.

## 6. Откат

- Код: остановите панель (`systemctl stop clinic-admin`), верните бота на прежний
  коммит (`git checkout e6018b4 && npm ci`) и перезапустите его. Старая версия читает
  базу v5: новые таблицы и столбцы ей не мешают, записи сохраняются. Но старый бот
  берёт врачей и расписание из кода, а не из базы, — изменения из панели он не увидит.
- База: восстанавливать из копии нужно только при повреждении (пропадут записи после
  копии). Остановите бота и панель, затем:
  ```bash
  cp -p ../bot-backups/bot-<дата>.sqlite .data/bot.sqlite
  rm -f .data/bot.sqlite-wal .data/bot.sqlite-shm
  ```

## 7. Проверка после развёртывания

1. `https://<домен>/admin` без входа → перенаправление на страницу входа;
   `https://<домен>/api/admin/dashboard` → 401; `https://<домен>/` → 404 (сайт закрыт).
2. Вход созданным администратором. Неверный пароль — «Неверный логин или пароль.»;
   после 5 ошибок — пауза 15 минут.
3. Главная: «Бот ВКонтакте работает», если бот опрашивал ВКонтакте последние 2 минуты.
4. Запись через бота с тестового аккаунта → появляется в разделе «Записи» (источник
   «ВКонтакте»).
5. «Новая запись» на свободное время → в боте это время больше не предлагается.
6. «Врачи» → изменить стоимость приёма → в боте «Сколько стоит приём?» показывает
   новую цену. Отключить врача → бот его не предлагает.
7. «Расписание» → выходной на завтра → бот не предлагает этот день.
8. «Настройки» → телефон → бот показывает его в ответе об адресе.
9. Отмена записи в панели → время снова свободно (и в боте).
10. Счётчики бота — `npm run bot:stats`; журнал действий сотрудников — таблица
    `admin_audit` (без персональных данных); попытки открыть сведения — раздел
    «Журнал доступа» (владелец).
11. Роли — раздел 6 `docs/privacy-update-vps.md`.

## 8. Ограничения

- Демонстрация: данные клиники вымышленные. Поле «Пометка» в ручной записи — не для
  ФИО, телефонов и жалоб: сервер отклоняет пометки с жалобами, симптомами, телефонами и
  почтой (проверка эвристическая). Реальные персональные данные не собираются до
  правовой оценки.
- Переписку пациента в сообщениях сообщества видят руководители сообщества ВКонтакте —
  роли панели этого не ограничивают (`docs/medical-privacy.md`, раздел 1).
- Бот не уведомляет пациента ВКонтакте об отмене или переносе из панели — администратор
  пишет пациенту сам в сообщениях сообщества.
- Выходной, добавленный на время с уже подтверждёнными записями, не отменяет их —
  панель сообщает, сколько записей нужно перенести.
- Подбор специалиста по жалобам в боте знает прежние направления; новые специальности
  из панели доступны для записи через меню.
- Ограничение попыток входа хранится в памяти процесса панели и сбрасывается при
  перезапуске.
