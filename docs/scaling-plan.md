# План масштабирования «Демо-Мед»: 5, 20, 50 и 100 клиник

Аудит 28.10.2026 по коду и нагрузочным тестам. Ничего не переделано, не развёрнуто и не
куплено. Источники замеров:

- `docs/load-test-report.md` — HTTP (Mini App и панель), гонка за слот, SQLite,
  модель 20 клиник;
- `docs/vk-bot-concurrency-report.md` — VK-бот до и после параллельной обработки
  (ветка `claude/bot-concurrency`).

**Обозначения:** **[замер]** — измерено локально (4 vCPU Xeon 2,1 ГГц, сервер на 2
ядрах); **[расчёт]** — выведено из замеров, не проверено; **[нужны данные]** — без
внешних данных не определить. Задержки ВКонтакте (100 мс) и OpenAI (1,5 с) в тестах —
допущения заглушек.

## 1. Главное

1. **Один процесс Node.js использует одно ядро.** Сайт, панель и Mini App — один процесс
   `next start`: он упирается в 1 ядро при ~65–70 запросах в секунду ≈ 150 одновременно
   активных пациентов Mini App при p95 < 2 с **[замер]**. Больше ядер помогают только
   при нескольких процессах — сами по себе они не ускоряют один процесс.
2. **Текущая архитектура — «экземпляр на клинику»:** одна клиника = свой процесс сайта и
   панели (0,22 ГБ в покое, до ~0,35–0,47 ГБ под нагрузкой) + свой процесс бота
   (0,12–0,26 ГБ) **[замер]**. До ~20 клиник это работает; на 50–100 упирается в память.
3. **Бот одного сообщества не быстрее лимита VK API** — 20 запросов в секунду на ключ
   сообщества; при `VK_API_RPS=15` замерено ровно 15 ответов в секунду **[замер]**.
   Для одной клиники это ~100 одновременных пациентов с ответом < 1 с.
4. **OpenAI — главная переменная стоимость и общий лимит** для всех клиник одного
   аккаунта. Цены и лимиты отсюда подтвердить не удалось **[нужны данные]**.
5. **SQLite на одном сервере не узкое место** **[замер: 0 блокировок, 0 двойных
   записей]**; PostgreSQL нужен при нескольких серверах или отказоустойчивости.

## 3. Сравнение конфигураций VPS

Ёмкость по замерам **[расчёт]**:

- **Память на клинику при текущей архитектуре:** сайт и панель 0,22 ГБ в покое; под
  нагрузкой в модели 20 клиник — 7,1 ГБ / 20 = 0,36 ГБ. Бот 0,12–0,26 ГБ. Итого
  **≈ 0,5 ГБ на клинику** обычно, **до ~0,7 ГБ** в пике. Плюс ~0,5–1 ГБ на ОС, nginx и
  запас. Сборку (`next build`, до 1,5 ГБ) — на другой машине.
- **CPU:** ~150 активных пациентов Mini App на ядро до насыщения; держать **≤ 50–60%
  загрузки** в ожидаемый пик — выше p95 растёт резко (76% CPU → p95 0,3 с; 98% → 1,0 с;
  > 100% → тайм-ауты) **[замер]**. Отсюда **≈ 75 активных пациентов на ядро с запасом**.
- Скорость одного ядра у VPS может отличаться от тестовой (Xeon 2,1 ГГц) — проверить
  `scripts/load/run-http.mjs` на выбранном тарифе.

| Конфигурация    | Архитектура «экземпляр на клинику» (как сейчас)                                             | Общая платформа (после переделки, раздел 6)                                                                     |
| --------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 4 vCPU / 8 ГБ   | **до ~10 клиник** (память 5–7 ГБ); CPU: до ~300 активных пациентов на все клиники с запасом | ~3 процесса сайта + бот: ~225–300 активных пациентов с запасом; 20+ клиник, если в пике у клиники ≤ 10 активных |
| 8 vCPU / 16 ГБ  | **до ~20 клиник** (10–14 ГБ); CPU: ~600 активных с запасом                                  | ~7 процессов: ~500–600 активных; 50 клиник при ≤ 10 активных в пике                                             |
| 16 vCPU / 32 ГБ | **~40 клиник** по памяти; 50–100 — не помещаются                                            | ~14 процессов: ~1000–1200 активных; 100 клиник при ≤ 10 активных в пике                                         |

Нелинейность: удвоение ядер удваивает ёмкость только при числе процессов не меньше
числа ядер (при «экземпляре на клинику» это так; у одного процесса — нет). Лимит VK —
на сообщество, OpenAI — на аккаунт: от VPS они не зависят.

Сколько одновременно активных пациентов бывает у одной клиники в пике — **[нужны данные]**
(после первых клиник — счётчики бота и Mini App).

### 4.2. OpenAI

Запрос к модели **[замер по коду]**: инструкции 7 031 символ (65% кириллица) + JSON-схема
1 839 + до 12 последних реплик и состояние — ~10–10,5 тыс. символов на запрос. В модель
не уходят кнопки, «да/нет» на подтверждении, экстренные сообщения, приветствия, оффтоп
и спам.

Оценка токенов **[расчёт]**: ~3 000–4 500 входных и ~300–800 выходных (JSON-решение и
рассуждение `effort: low`) на запрос. Точное значение — usage в кабинете OpenAI после
первых дней работы. Инструкции одинаковы у всех запросов клиники — часть входа может
оплачиваться по сниженной цене кэша.

Цена модели `gpt-5.6-luna` — **не подтверждена**: официальная страница недоступна,
агрегаторы расходятся — $0,20 / $1,20 за 1 млн входных/выходных токенов (август 2026) и
$1,00 / $6,00 (июль 2026). Расчёт для обеих:

| Запросов к модели на клинику в месяц | При $0,20 / $1,20 | При $1,00 / $6,00 |
| ------------------------------------ | ----------------- | ----------------- |
| 1 000                                | $1,0–1,9          | $4,8–9,3          |
| 5 000                                | $4,8–9,3          | $24–47            |
| 20 000                               | $19–37            | $96–186           |

На все клиники при 5 000 запросов на клинику в месяц:

| Клиник | При $0,20 / $1,20 | При $1,00 / $6,00 |
| ------ | ----------------- | ----------------- |
| 5      | $24–47            | $120–233          |
| 20     | $96–186           | $480–930          |
| 50     | $240–465          | $1 200–2 325      |
| 100    | $480–930          | $2 400–4 650      |

Формула: запросы × (вход × цена входа + выход × цена выхода) / 1 000 000.
`OPENAI_DAILY_REQUEST_LIMIT=500` по умолчанию ограничивает клинику ~15 000 запросов в
месяц. Курс и комиссия оплаты — **[нужны данные]**. Отдельный риск — оплата и
доступность OpenAI из России и передача текста пациентов за рубеж (152-ФЗ) — решение
владельца и юриста.

### 4.3. Резерв на пик

- CPU: в ожидаемый пик не выше 50–60% — двукратный запас **[по замерам: выше ~75% p95
  растёт резко]**.
- Память: не выше 70–75% — запас на всплески и обновление.
- VK: держать `VK_API_RPS` ≤ 15 из 20 — уведомления администратору идут тем же ключом.
- OpenAI: `OPENAI_CONCURRENCY` не выше лимитов аккаунта, суточный лимит — по бюджету;
  при исчерпании бот отвечает по правилам (замерено: без ошибок у пациентов).

### 4.4. Себестоимость клиники

Себестоимость клиники в месяц = хостинг / число клиник + OpenAI клиники + бэкапы и
мониторинг / число клиник + время поддержки.

Пример **только для иллюстрации формулы** (цены не подтверждены): 20 клиник на 8 vCPU /
16 ГБ за 2 777 ₽ → хостинг ≈ 139 ₽ на клинику; OpenAI при 5 000 запросов — $4,8–47 на
клинику в зависимости от цены модели. Переменная часть (OpenAI) почти наверняка больше
хостинга — её и нужно уточнять первой.

## 7. Чего не хватает для точных расчётов

1. Характеристики и тариф действующего VPS.
2. Цены выбранного провайдера (с выделенными vCPU и сегментом для ПДн).
3. Цена и лимиты OpenAI для `gpt-5.6-luna` на вашем аккаунте, реальные токены запроса.
4. Объём: пациентов в день на клинику, сообщений на пациента, пиковая одновременность.
5. Повторить нагрузочный тест (`scripts/load/`) на выбранном тарифе — один прогон
   уровней 50–200 даст реальную ёмкость ядра VPS.
