# Обновление VPS до этапа 2: роли и медицинская конфиденциальность

Инструкция для того, кто обслуживает VPS (например, Claude Desktop). Сейчас на VPS
работает коммит `a27d6779b116ac74c35f05c088de9cddaed4132b` (бот + панель, схема базы v5).
Пути, имена сервисов и домен не выдумываются — подставьте свои вместо `<…>`. Секреты в
чат, в Git и в журналы не попадают.

Что меняется — `docs/medical-privacy.md`. Коротко:

- у сотрудников панели появляются роли `owner` / `admin` / `doctor`;
- **существующая учётная запись (созданная `npm run admin:user -- create`) становится
  `owner` (владелец)**: пароль и открытые сессии сохраняются, вход — как раньше;
- владелец получает разделы «Сотрудники» и «Журнал доступа», настройки клиники теперь
  только у владельца;
- врачи входят по приглашению и видят только свои приёмы;
- бот предупреждает пациента, что переписку в сообщениях сообщества видят
  администраторы сообщества ВКонтакте, и может (по желанию пациента) передать врачу
  записи краткое описание жалобы — только если задан `MEDICAL_DATA_KEY`.

## 1. Подготовка

Работайте под пользователем, от которого запущены бот и панель, в каталоге проекта.

```bash
git status --short            # локальные изменения не затирать — сначала разобраться
git rev-parse HEAD            # ожидается a27d677…; запомнить для отката
node -v                       # 24.x
free -m && swapon --show      # для сборки нужен swap (docs/admin-panel-deploy.md, раздел 4)
```

## 2. Резервная копия базы (обязательно)

Без остановки бота:

```bash
npm run db:backup             # → ../bot-backups/bot-<дата>.sqlite
ls -la ../bot-backups/ | tail -3
```

Копия содержит записи и учётные записи. Храните её вне каталога проекта.

## 3. Ключ шифрования (рекомендуется)

Сгенерируйте ключ **на сервере** и добавьте в `.env.local` (его читают и бот, и панель):

```bash
grep -q '^MEDICAL_DATA_KEY=' .env.local && echo "ключ уже есть — не перезаписывать" || \
  node -e "console.log('MEDICAL_DATA_KEY=' + require('crypto').randomBytes(32).toString('base64'))" >> .env.local
chmod 600 .env.local
```

Не выводите ключ в терминал чата и не копируйте его в сообщения. Сохраните `.env.local`
(или только ключ) в отдельное защищённое место, **отдельно от резервных копий базы**:
без ключа зашифрованные сведения не прочитать, а с ключом и копией базы — прочитать всё.

Без ключа всё работает, но разговоры хранятся без шифрования, а передача сведений врачу
выключена.

Необязательно: `BOT_MEDICAL_QUESTIONS=false` — бот не расспрашивает о симптомах во
ВКонтакте (рекомендуется для реальных пациентов, пока медицинская часть не вынесена из
ВКонтакте — `docs/medical-privacy.md`, раздел 1).

## 4. Код, зависимости, проверки, сборка

```bash
git fetch origin claude/jolly-bohr-j26x8f
git checkout claude/jolly-bohr-j26x8f
git pull --ff-only origin claude/jolly-bohr-j26x8f

NODE_OPTIONS=--max-old-space-size=1024 npm run build
```

Если сборка падает по памяти — `docs/admin-panel-deploy.md`, раздел 4.

## 5. Перезапуск

Тем же способом, каким запущены сервисы (`systemctl restart <бот>` и
`systemctl restart clinic-admin`, или `pm2 restart …`). Порядок не важен: миграция v6
применяется один раз тем процессом, который откроет базу первым (`BEGIN IMMEDIATE`).

В журнале бота: `схема v6`, `long poll: connected`, `шифрование и передача врачу:
включены` (или `выключены (нет MEDICAL_DATA_KEY)`).

Миграция v6 не удаляет и не меняет записи, врачей, расписание, настройки и пароли:
добавляет столбцы `role`, `doctor_id` в `admin_users` (все существующие → `owner`) и
таблицы `staff_invites`, `disclosure_consents`, `medical_access_log`.

## 6. Проверка

1. `npm run admin:user -- list` — прежний логин с ролью «владелец».
2. Вход в панель прежним логином и паролем. В меню: Главная, Записи, Врачи, Расписание,
   Настройки, Сотрудники, Журнал доступа.
3. «Сотрудники» → «Пригласить» → роль «Врач», врач расписания → ссылка. Открыть ссылку
   в приватном окне, задать пароль, войти: в меню только «Мои приёмы»; `/admin/bookings`
   перенаправляет на «Мои приёмы»; `https://<домен>/api/admin/bookings` → 403.
4. Пригласить роль «Администратор»: нет «Настроек», «Сотрудников», «Журнала доступа».
5. Бот: «Начать» — в приветствии предупреждение о видимости переписки. Жалоба → запись →
   (при заданном ключе) кнопка «Передать врачу описание» → предпросмотр → «Передать
   врачу». Врач этой записи видит «Сведения от пациента»; другой врач и администратор —
   нет. Владелец видит событие в «Журнале доступа» без содержания.
6. «Мои записи» в боте → «Отозвать сведения №…» → у врача сведения пропадают.
7. «Позвать администратора» — бот предупреждает, что администратор увидит всю
   переписку диалога во ВКонтакте; уведомление администратору — только ссылка.
8. `npm run bot:check` — строка про `MEDICAL_DATA_KEY` и предупреждение о ВКонтакте.

## 7. Откат

1. Перед откатом **отключите учётные записи врачей и администраторов**, созданные после
   обновления: в версии `a27d677` ролей нет, и любой вошедший получит все разделы
   (медицинских данных старая панель не показывает):
   ```bash
   npm run admin:user -- list
   npm run admin:user -- disable <логин>
   ```
2. Код: `git checkout a27d6779b116ac74c35f05c088de9cddaed4132b && npm ci &&
NODE_OPTIONS=--max-old-space-size=1024 npm run build`, перезапустить бот и панель.
   Старая версия читает базу v6: лишние столбцы и таблицы ей не мешают. Зашифрованные
   разговоры старый бот не прочитает — эти пациенты просто начнут диалог заново; записи
   на приём не зашифрованы и сохраняются.
3. Базу из копии восстанавливать только при повреждении (пропадут записи после копии):
   остановить бот и панель, затем
   ```bash
   cp -p ../bot-backups/bot-<дата>.sqlite .data/bot.sqlite
   rm -f .data/bot.sqlite-wal .data/bot.sqlite-shm
   ```

## 8. Что не делать

- Не публиковать ключ, токены и пароли в чатах и журналах.
- Не выдавать роль «Врач» сотрудникам, которые не являются врачом этой записи.
- Не обещать пациентам, что переписка во ВКонтакте конфиденциальна: её видят
  руководители сообщества (`docs/medical-privacy.md`, раздел 1).
