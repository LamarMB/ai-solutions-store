# Готовность к production

Аудит этапа 10 (14.10.2026, ветка от `main` fdb1497). Сайт **не готов к публичному
запуску**: есть юридические и инфраструктурные блокеры, перечисленные ниже. Технически
приложение собирается, проходит тесты и браузерные проверки; приём заявок и консультант
работают в тестовом/демонстрационном режиме намеренно.

Связанные документы: [deployment-plan.md](deployment-plan.md) — развёртывание,
[launch-checklist.md](launch-checklist.md) — пошаговый чек-лист, [requests.md](requests.md),
[consultant.md](consultant.md), [seo.md](seo.md).

## 2. Исправлено в этапе 10

1. **Обход ограничения частоты подменой `X-Forwarded-For`.** Ключ клиента строился из
   _первого_ адреса заголовка, который присылает сам клиент: подставляя каждый раз новый
   адрес, можно было обойти лимит заявок (8 за 10 минут) и консультанта (30 в минуту).
   Теперь берётся последний адрес — его добавляет доверенный прокси или Next.js
   (`src/lib/client-key.ts`, тесты). Код вынесен из двух Server Actions в один модуль.
   Для production прокси обязан перезаписывать заголовок (см. `deployment-plan.md`).
2. **Страницы ошибок.** Добавлены `app/error.tsx` и `app/global-error.tsx` на русском в стиле
   сайта, с кнопкой повтора и кодом ошибки. Раньше показывалась стандартная английская
   страница Next.js. Проверено на временном падающем маршруте: статус 500, детали ошибки
   пользователю не передаются.
3. **Заголовки безопасности** для всех ответов (`next.config.ts`): `X-Content-Type-Options:
nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`,
   `Permissions-Policy` (камера, микрофон, геолокация выключены) и CSP с
   `frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'`.
4. **Тест на тестовое хранилище:** `getRequestStore()` остаётся `TestRequestStore` даже при
   заданных `DATABASE_URL` и подобных переменных — случайно включить сохранение нельзя.

## 5. План реального приёма заявок

Сейчас — только тестовый режим. Включать после K2, K3, K5.

1. **Хранилище.** Managed PostgreSQL в российском регионе облака (резервные копии и
   шифрование диска — средствами провайдера). Таблица `requests`: id, created_at,
   items (jsonb: solutionId, packageId), name, company, contact_method, contact_value,
   message, status, delete_after. Без IP, user-agent и служебных полей.
   Реализовать `DatabaseRequestStore implements RequestStore`, режим `"live"` в
   `IntakeMode`; выбор адаптера в `getRequestStore()` — **явным** флагом
   (`REQUEST_INTAKE=live`) плюс наличием строки подключения; без обоих — тестовый режим.
2. **Безопасное хранение контактов.** Доступ к БД только из приватной сети приложения;
   учётная запись приложения с правами `INSERT` (без `SELECT` всех заявок);
   отдельная роль для просмотра. Строка подключения — в секретах окружения, не в Git.
   Дополнительно возможно шифрование поля контакта на уровне приложения (ключ — в
   менеджере секретов облака).
3. **Уведомления.** Письмо или сообщение ответственному **без персональных данных**: «новая
   заявка #id, решение X» со ссылкой во внутренний интерфейс. Почтовый сервис — в РФ.
4. **Спам.** Уже есть: ловушка, минимальное время, ключ повторной отправки, лимит частоты.
   При запуске — общий счётчик лимита в БД/Redis, проверка доверенного прокси; при росте
   спама — капча российского провайдера (SmartCaptcha) отдельным решением.
5. **Резервное копирование.** Автоматические бэкапы managed-БД (ежедневно, хранение 7–30
   дней по политике), проверка восстановления раз в квартал.
6. **Контроль доступа.** Просмотр заявок — только сотрудникам по списку, с двухфакторной
   аутентификацией в облаке; журнал доступа средствами провайдера.
7. **Удаление.** Срок хранения задаётся политикой (K2). Ежедневная задача удаляет записи с
   истёкшим `delete_after`; удаление по запросу субъекта — по id заявки или контакту.
   Бэкапы с удалёнными данными истекают по своему сроку хранения.

**Оценка расхода.** Ответ консультанта ≈ 5–7 тыс. входных токенов (данные каталога + история)
и до 500 выходных. При ~1 ₽ за 1000 токенов — около 6–8 ₽ за ответ, ~6–8 тыс. ₽ на 1000
ответов в месяц. Это оценка порядка, не расчёт: зависит от модели и длины диалогов.

**Защита от выдуманных рекомендаций** (большая часть уже в коде):

- провайдер возвращает только `solutionId` и причину; карточки, цены и статусы берутся из
  каталога (`resolveRecommendations`), неизвестные id отбрасываются;
- структурированный ответ (JSON по схеме Zod), при ошибке разбора — честный отказ;
- системный промпт с данными каталога, статусами `concept`/`in_development` и запретом
  обещать сроки, цены и результаты; причина для концепций обязана содержать статус —
  проверка на сервере, как сейчас в mock;
- история с клиента не доверенная: реплики «ассистента» могут быть подделаны —
  пересобирать контекст на сервере или подписывать ответы;
- регрессионные тесты `src/consultant/` на новом провайдере.

**Контроль расходов:** лимит `max_tokens` ответа; обрезка истории (уже ≤ 30 реплик, ≤ 1000
символов на сообщение); существующий лимит 30 запросов в минуту на клиента; суточный
бюджет на уровне приложения (счётчик токенов, при превышении — возврат к mock с
пояснением); бюджетные уведомления в биллинге облака; ключ API — в секретах окружения.
