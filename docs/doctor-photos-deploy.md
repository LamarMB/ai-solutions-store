# Обновление VPS: фотографии врачей (этап 20)

Инструкция для Claude Desktop. Пути, имена сервисов и логины — свои вместо `<…>`.
Секреты не выводить в чат, не коммитить и не писать в журналы. Развёртывание — только
по решению владельца.

Если на сервере ещё нет предыдущих этапов (схема ниже v7) — сначала
`docs/bot-menu-requests-deploy.md` (разделы 2–4: что стоит, резервная копия,
переменные), затем продолжить здесь: обновление кода одно и то же.

## 1. Что меняется

- **Миграция базы v8** — таблица `doctor_photos` (фото как BLOB в той же базе
  `BOT_DB_PATH`). Записи, врачи, расписание, сотрудники, согласия и обращения не меняются.
- **Админ-панель, «Врачи» → «Фото»:** загрузка с предпросмотром, замена, удаление (роли
  «Владелец» и «Администратор»). JPEG, PNG, WebP; в браузере — обрезка до квадрата
  800×800, на сервере — проверка по содержимому, до 2 МБ.
- **Mini App:** фото на главной, в списке врачей, в карточке врача, при выборе врача, в
  форме записи, подтверждении и «Моих записях»; без фото — монограмма.
- **Демо-портреты** шести вымышленных врачей (созданы ИИ, пометка в приложении) —
  только командой `npm run doctors:demo-photos`, автоматически не ставятся.

## 2. Где хранятся фото и как их не потерять

- Фото — **внутри базы** (`.data/bot.sqlite` или ваш `BOT_DB_PATH`). Отдельной папки
  загрузок нет; `git pull`, `npm ci`, сборка и перезапуск их не трогают.
- Резервная копия — как раньше: `npm run db:backup` (фото входят в копию).
- **Не удалять и не пересоздавать базу** при обновлении; не восстанавливать старую копию
  без необходимости — пропадут фото и записи, сделанные после неё.

## 3. Порядок обновления

```bash
cd <каталог проекта>
git status --short                      # локальные изменения не затирать
git rev-parse --short HEAD              # точка отката — записать
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync(process.argv[1],{readOnly:true});console.log('схема v'+db.prepare('PRAGMA user_version').get().user_version)" "${BOT_DB_PATH:-.data/bot.sqlite}"

npm run db:backup                       # → ../bot-backups/bot-<дата>.sqlite
ls -la ../bot-backups/ | tail -3

git fetch origin claude/jolly-bohr-j26x8f
git checkout claude/jolly-bohr-j26x8f
git pull --ff-only origin claude/jolly-bohr-j26x8f
npm ci
npx vitest run src/bot src/admin src/miniapp          # мок-данные, рабочую базу не трогает
NODE_OPTIONS=--max-old-space-size=1024 npm run build  # swap обязателен (admin-panel-deploy.md, раздел 4)
```

Перезапустить **бота** и **панель** тем же способом, каким они запущены
(`systemctl restart <бот>` и `systemctl restart clinic-admin` или `pm2 restart …`).
Миграция v8 применяется один раз тем процессом, который первым откроет базу; в журнале
бота — `схема v8`.

## 4. Демо-портреты (один раз, только для демо-клиники)

```bash
npm run doctors:demo-photos
```

Ожидаемо: шесть строк `<id>: фото привязано`. Команда ставит фото только врачам, у
которых совпадают `id` и ФИО из демо-набора (Анна Тестова, Павел Примеров, Мария
Демонстрова, Игорь Макетов, Елена Образцова, Олег Вымыслов); уже загруженные фото не
заменяет (`-- --force` — заменить). Для клиники с реальными врачами **не запускать**.
Если в строке «имя врача изменено» — врача переименовали; это ожидаемо, фото не ставится.

## 5. nginx

Файл после обработки в браузере — 100–300 КБ, лимит сервера — 2 МБ. Стандартного
`client_max_body_size 1m` обычно хватает; если при загрузке ошибка 413 от nginx —
добавить `client_max_body_size 4m;` в блок `location /api/admin`, затем
`sudo nginx -t && sudo systemctl reload nginx`.

## 6. Проверка

1. `curl -sI https://<домен>/api/miniapp/photos/testova | head -1` → `200`;
   `…/photos/nobody` → `404`.
2. Панель → «Врачи»: у шести врачей миниатюры. «Фото» у одного врача → выбрать снимок с
   телефона → предпросмотр → «Сохранить фото» → миниатюра обновилась. «Удалить фото» →
   «нет фото». (Затем вернуть демо-портрет: `npm run doctors:demo-photos`.)
3. Mini App на iPhone и Android: фото на главной, в «Врачах», в карточке врача (крупно),
   в форме записи и «Моих записях»; под списком — пометка «портреты созданы ИИ».
   Запись, перенос и отмена работают как раньше.
4. Перезапустить панель ещё раз — фото на месте.
5. Под ролью «Врач» кнопки «Фото» нет; `PUT /api/admin/doctors/<id>/photo` → 403.

## 7. Откат

1. `git checkout <точка отката> && npm ci && NODE_OPTIONS=--max-old-space-size=1024 npm run build`,
   перезапустить бота и панель. Старая версия работает с базой v8: таблица
   `doctor_photos` ей не мешает, фото просто не показываются и остаются в базе до
   возврата новой версии.
2. Восстанавливать базу из копии — только при повреждении (пропадут записи и фото после
   копии): остановить бота и панель,
   `cp -p ../bot-backups/bot-<дата>.sqlite .data/bot.sqlite && rm -f .data/bot.sqlite-wal .data/bot.sqlite-shm`,
   запустить.
