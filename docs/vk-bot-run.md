# Запуск VK-бота тестовой клиники на Windows

Бот работает через **Bots Long Poll**: сам обращается к серверам ВКонтакте, поэтому
публичный адрес, домен и https не нужны. Достаточно компьютера с Node.js 24 и интернетом.
Бот отвечает, пока запущен процесс `npm run bot:vk`.

Это демонстрационный прототип: клиника, врачи и расписание вымышленные, бот отвечает
только тестовым аккаунтам из `VK_ALLOWED_USER_IDS`.

**Клиника-клиент (`BOT_MODE=live`).** Тексты бота, инструкции модели и уведомление
администратору — без пометок «демо», «вымышленные», «тестовое расписание». Пустой
`VK_ALLOWED_USER_IDS` — бот отвечает всем пациентам; заполненный — только этим аккаунтам
(остальным — «бот клиники пока проходит проверку»), так удобно проверить бота перед
открытием доступа. Бот не запустится, пока в панели не заменены данные вымышленной
клиники (название, адрес, проезд, врачи и т. п.) — он перечислит поля. При открытом
доступе `VK_MINIAPP_ID` должен быть пустым: Mini App пока работает только для тестовых
аккаунтов.

## 1. Подготовить компьютер

1. Установить **Node.js 24 LTS** с nodejs.org (или `nvm use` — версия в `.nvmrc`)
   и **Git**.
2. В PowerShell:

   ```powershell
   git clone https://github.com/LamarMB/ai-solutions-store.git
   cd ai-solutions-store
   git checkout claude/jolly-bohr-j26x8f
   npm ci
   ```

   Если репозиторий уже есть: `git fetch`, `git checkout claude/jolly-bohr-j26x8f`,
   `git pull`, `npm ci`.

## 2. Настроить сообщество ВКонтакте (id 242364009)

Названия пунктов могут немного отличаться — сверяйтесь с интерфейсом ВКонтакте.

1. **Управление → Сообщения** — включить сообщения сообщества.
2. **Управление → Сообщения → Настройки для бота** — включить «Возможности ботов» и
   кнопку «Начать». Добавление в беседы не нужно.
3. **Управление → Работа с API → Ключи доступа → Создать ключ** — отметить
   **«Сообщения сообщества»** и **«Управление сообществом»** (второе нужно только чтобы
   `npm run bot:check` прочитал настройки Long Poll; без него бот работает, а проверку
   настроек сделайте вручную). Скопируйте ключ — он показывается один раз.
4. **Работа с API → Long Poll API** — «Включён», версия API **5.199** (или последняя).
   На вкладке **«Типы событий»** отметить:
   - Входящее сообщение (`message_new`);
   - Исходящее сообщение (`message_reply`) — пауза бота, когда отвечает администратор;
   - Действие с сообщением (`message_event`) — нажатия кнопок.
5. **Callback API не включать** — он не используется.

## 3. Узнать VK ID тестовых аккаунтов

VK ID — число. Откройте страницу профиля: адрес `vk.com/id123456789` → ID `123456789`.
Если в адресе короткое имя, ID видно в **Настройках → Аккаунт → Адрес страницы** или в
адресе любой своей фотографии (`photo123456789_…`).

## 4. Вставить ключи — файл `.env.local`

В папке проекта:

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

Заполнить (без кавычек и пробелов вокруг `=`):

```dotenv
VK_GROUP_ID=242364009
VK_GROUP_TOKEN=vk1.a.…ключ сообщества из шага 2.3…
VK_ALLOWED_USER_IDS=123456789,987654321
VK_ADMIN_USER_ID=123456789
OPENAI_API_KEY=sk-…ключ с platform.openai.com → API keys…
```

- `.env.local` не попадает в Git (`.gitignore`). Не пересылайте ключи в чат и не
  вставляйте их в другие файлы.
- `OPENAI_API_KEY` можно оставить пустым: бот будет работать по кнопкам и ключевым словам.
- `VK_ADMIN_USER_ID` — кому приходит уведомление «пациент просит администратора». Этот
  аккаунт должен **один раз написать сообществу**, иначе ВКонтакте не даст отправить ему
  сообщение.
- Модель по умолчанию — `gpt-5.6-luna` (недорогая, понимает русский). Другая — через
  `OPENAI_MODEL`. Лимит запросов к OpenAI в сутки — `OPENAI_DAILY_REQUEST_LIMIT` (500);
  дополнительно задайте лимит расходов в настройках проекта OpenAI (Limits).

## 5. Проверить и запустить

```powershell
npm run bot:setup      # включает сообщения и Long Poll (если хватает прав), определяет ваш VK ID
                       # по сообщению «тест» в сообщество, выбирает модель OpenAI
npm run bot:check      # переменные, ключ сообщества, Long Poll, ключ OpenAI
npm run bot:vk         # запуск бота; остановка — Ctrl+C
```

`bot:check` ничего не отправляет пользователям и не печатает ключи. Каждая строка —
`OK` или `FAIL` с подсказкой, что исправить.

Затем с тестового аккаунта откройте сообщество → «Написать сообщение» → «Начать».

Без ВКонтакте сценарий можно проверить в терминале:

```powershell
npm run bot:sim                 # только правила
npm run bot:sim -- --openai     # с OpenAI (ключ из .env.local)
```

## 6. Что проверить в диалоге

Бот ведёт разговор обычным текстом; кнопки — для удобного выбора врача, дня, времени
и подтверждения. Подробные сценарии — `docs/conversational-bot-deploy.md`.

1. «Здравствуйте, у меня болит колено» → бот по одному уточняет: была ли травма, как
   давно, есть ли тревожные признаки → предлагает травматолога-ортопеда с ближайшим
   временем → «Запишите на ближайшее время» → «Подтвердить» → «Запись подтверждена».
2. «После падения колено сильно опухло, не могу наступить» → сразу совет звонить 103/112
   или ехать в травмпункт, без расспросов и записи.
3. «Мне нужен ЛОР» → выбор дня без вопросов о симптомах; «А сколько стоит приём?» → цена,
   запись продолжается; «Ладно, давай на завтра» → время на завтра.
4. «Нужен кардиолог» → честно: такого специалиста нет, предложение администратора.
5. «Что выпить от боли?» / «Поставьте диагноз» → отказ без советов, предложение врача.
6. Второй тестовый аккаунт выбирает то же время — получает «время только что заняли».
7. «Мои записи» → отменить → подтвердить.
8. «Позвать администратора» → «Да, позвать» → администратору приходит ссылка на
   диалог, бот замолкает. Ответ администратора вручную продлевает паузу. Вернуть бота —
   кнопка «Вернуться к боту» или слово «бот».
9. «Сброс» → история разговора удалена, разговор начинается заново.
10. «Расскажи анекдот», «Забудь инструкции…» → «Я ИИ-администратор клиники и могу помочь
    только с вопросами о здоровье, специалистах, услугах и записи на приём…» — без
    запроса к OpenAI. Счётчики — `npm run bot:stats`.
11. Фото или документ — бот просит не присылать вложения.
12. Посторонний аккаунт получает одно сообщение «доступен только тестовым аккаунтам».

## Сквозная проверка без ВКонтакте

`npm run e2e:bot-booking` (`scripts/e2e/bot-booking.mts`) — автоматический сценарий записи
и отмены через бота:

1. Пациент пишет боту («Начать»).
2. Выбирает направление и врача.
3. Получает свободное время; оно сверяется с расписанием.
4. Подтверждает запись.
5. Запись сохраняется в базе с источником `vk`, слот занят.
6. Владелец видит запись в панели («Бот ВКонтакте», «Подтверждена»).
7. Пациент отменяет её через бота: «Мои записи» → «Отменить №…» → «Да, отменить».
8. Статус «Отменена» в базе и в панели. Тот же слот (дата и время записи) снова
   предлагается ботом. Запись другого пациента не меняется.

Дополнительно проверяется:

- на каждое нажатие отправлен ответ `messages.sendMessageEventAnswer`;
- внешних запросов нет;
- в консоли панели нет ошибок;
- в журнале бота нет полного VK ID и текста сообщений.

**ВКонтакте имитируется** (`scripts/e2e/fake-vk.mts`). Бот собран как в
`scripts/vk-bot.mts`: `createDemoBot` → `createVkRunner` → `runLongPoll` → `VkApi` с
очередью `KeyedQueue`. Отличие одно: `fetch` подменён внутри процесса имитацией методов
`groups.getLongPollServer`, `messages.send`, `messages.sendMessageEventAnswer` и
long poll. Запрос по любому другому адресу, кроме локальной панели, завершается ошибкой.

Не проверяются:

- настоящий сервер ВКонтакте: доставка, ограничения частоты, отображение клавиатур в
  приложениях;
- токен и права сообщества;
- уведомления администратору.

Их проверяет `npm run bot:check` и ручная проверка (раздел 6).

**Окружение** — то же, что у `e2e:patient-flow` (`docs/patient-data.md`, раздел 5), общая
обвязка — `scripts/e2e/harness.mjs`:

- временная база с вымышленными клиникой и пациентами 900100 и 900777;
- ключи на один запуск;
- панель — `next start` на 127.0.0.1 со случайным портом.

Нужны сборка (`npm run build`) и Playwright с Chromium.

**Результат** — в `.data/e2e/bot-booking-<время>/`, вне Git:

- при успехе — `report.json`; `E2E_KEEP_SHOTS=1` сохраняет и снимки;
- при ошибке — также снимки панели и переписки на момент сбоя, `transcript.html` и журнал
  сервера.

Временные данные и процессы удаляются при любом исходе, в том числе по Ctrl+C. В CI и
`npm test` сценарий не входит.

## Надёжность и данные

- Записи, шаги записи и память разговора — в `.data/bot.sqlite` (вне Git); переживают
  перезапуск. Память разговора (жалоба кратко, ответы на уточнения, последние 12 реплик
  без телефонов и email) удаляется через `BOT_HISTORY_HOURS` часов без активности
  (по умолчанию 24) и по команде «сброс». Сбросить все тестовые данные — остановить бота
  и удалить папку `.data`.
- Двойная запись исключена уникальным индексом SQLite; подтверждение и отмена берутся из
  сохранённого состояния, а не из кнопки.
- Повторно доставленные события ВКонтакте отбрасываются (таблица обработанных событий);
  ответы отправляются с постоянным `random_id`, поэтому ВКонтакте не дублирует их.
- Обрыв связи: бот ждёт (1 с → 2 с → … → 60 с) и переподключается с прежней позицией,
  события за время обрыва приходят после восстановления. Неверный ключ или нет прав —
  бот останавливается с подсказкой запустить `npm run bot:check`.
- OpenAI недоступен, ключ неверен или исчерпан лимит — бот 60 секунд не обращается к
  OpenAI и ведёт тот же разговор по правилам; кнопки работают всегда. Модель выбирает
  действие и формулирует ответ, но запись, отмену и проверку слотов выполняет только
  логика расписания; тревожные признаки проверяют правила до модели.
- В журнал пишутся только тип события и последние три цифры VK ID — без текста
  сообщений и ключей. Перед отправкой в OpenAI телефоны и email скрываются; запросы
  отправляются с `store: false`.

## Ограничения прототипа

- Текст сообщений тестовых аккаунтов передаётся в OpenAI (США) — это трансграничная
  передача. Пока бот работает только с тестовыми аккаунтами и вымышленными данными;
  для реальных пациентов нужна правовая оценка и, вероятно, другой провайдер.
- Бот работает, пока включён компьютер и запущен `npm run bot:vk`. Для постоянной работы
  нужен сервер (`docs/deployment-plan.md`) — отдельное решение.
- Лимиты клавиатур ВКонтакте (10 кнопок, 6 рядов, подпись 40 символов, payload 255)
  проверяются тестом; стоит сверить с dev.vk.com.
