# Правила: VK-бот и админ-панель

Обязательны перед изменением `src/bot/`, `src/admin/`, `src/app/admin/`, `src/app/api/admin/`,
`src/components/admin/` и `scripts/`. Перенесено из AGENTS.md без изменений; общие правила,
роли и конфиденциальность — в [AGENTS.md](../../AGENTS.md).

## VK-бот (прототип)

- План и статус — `docs/vk-bot-plan.md`; код — `src/bot/`, симулятор — `npm run bot:sim`.
- Бизнес-логика не знает о ВКонтакте и LLM: канал вызывает `createBot(...).handle()`,
  разговор ведёт `src/bot/conversation/orchestrator.ts`, LLM подключается как
  `ConversationModel`, МИС — как `ScheduleProvider`. Подробности —
  `docs/conversational-bot-deploy.md`.
- Только вымышленная клиника и данные. Бот не собирает документы, анализы, фото, ФИО и
  телефоны. Для маршрутизации хранится минимум: краткая жалоба, ответы на уточнения
  (травма, длительность, тревожные признаки), последние 12 реплик без контактов — в
  SQLite, не дольше `BOT_HISTORY_HOURS` (24 ч) и до команды «сброс». В журнал — никогда.
- Бот честно предупреждает (`PRIVACY_NOTICE`, `HANDOFF_QUESTION`), что переписку видят
  администраторы сообщества ВКонтакте. `BOT_MEDICAL_QUESTIONS=false` — без вопросов о
  симптомах. Описание жалобы врачу — только по согласию пациента (`src/bot/consent.ts`).
- Бот — административная маршрутизация, не диагностика: без диагнозов, лекарств,
  лечения и успокоения («ничего страшного»). Тревожные признаки проверяет
  `src/bot/conversation/safety.ts` (правила с учётом отрицаний) до модели; модель может
  повысить срочность, но не отменить правило. При экстренных признаках — сразу 103/112,
  без расспросов и записи. Ответы модели с лекарствами, диагнозами, временем и ценами
  отбрасываются (`isUnsafeReply`); время и цены показывает программа из справочника.
- Бот отвечает только на задачи клиники. Явный оффтоп и смена роли отклоняются фильтром
  `src/bot/conversation/scope.ts` до OpenAI точным шаблоном `OUT_OF_SCOPE_TEXT` (текст
  не менять без решения владельца); смешанное сообщение обрабатывается только в
  разрешённой части; сомнительное не блокируется. Правила безопасности идут до фильтра:
  тревожный признак внутри оффтопа получает экстренный ответ. Модель на оффтоп
  отвечает действием `out_of_scope`. Повторный оффтоп — пауза, спам и частота —
  `src/bot/conversation/guard.ts`; счётчики `stats` — только количества, без текста.
- Справочники клиники (врачи, специальности, часы, выходные, услуги, настройки) — в SQLite,
  а не в коде: `src/bot/storage/clinic-store.ts`; бот читает их через `ClinicSource`
  (`store.clinic.load()`, кэш до изменения базы). `fictionalClinic` — только начальные
  данные миграции v4 и тесты. Миграции — `PRAGMA user_version` в `src/bot/storage/sqlite.ts`.
- Записи — SQLite (`node:sqlite`, файл `.data/bot.sqlite` вне Git). Двойное бронирование
  исключено уникальным индексом по активному слоту; подтверждение и отмена — только из
  сохранённого состояния, не из данных кнопки.
- Кнопки укладываются в ограничения ВКонтакте (проверяется тестом): до 10 кнопок и 6 рядов,
  подпись до 40 символов, payload до 255 символов — сверить с dev.vk.com.
- Канал ВКонтакте — `src/bot/vk/`: только **Bots Long Poll** (Callback API не используется),
  запуск `npm run bot:vk`, проверка настроек `npm run bot:check`, инструкция —
  `docs/vk-bot-run.md`. Бот отвечает только `VK_ALLOWED_USER_IDS`; повторные события
  отбрасываются по таблице `processed_events`, `random_id` детерминирован.
- LLM — `OpenAiConversationModel` (`src/bot/llm/`, Responses API через `fetch`, без SDK,
  Structured Outputs). Модель возвращает действие из `MODEL_ACTIONS` и короткий ответ;
  решение проверяется `sanitizeDecision` (id врачей, даты, текст). Подтверждения и отмены
  записи среди действий нет: запись — только кнопкой «Подтвердить» или «да» на шаге
  подтверждения. Ошибка, лимит или неверный JSON — тот же разговор по правилам
  (`RuleInterpreter` + `triage.ts`). Новые проверки разговора — с мок-моделью, без API.
- Настройки — `src/bot/config.ts` (Zod), секреты только в `.env.local`; ошибки и журнал —
  без значений ключей и текста сообщений, VK ID маскируется (`maskId`).

## Админ-панель клиники

- Страницы `src/app/admin/` (вход — `/admin/login`, остальное — группа `(panel)` с проверкой
  сессии на сервере), API — `src/app/api/admin/[...path]` → `src/admin/api.ts`, операции —
  `src/admin/service.ts`, проверка данных — `src/admin/schemas.ts` (Zod), интерфейс —
  `src/components/admin/`. Развёртывание — `docs/admin-panel-deploy.md`.
- Один источник данных с ботом: та же база `BOT_DB_PATH` и то же расписание `ClinicSchedule`.
  Отдельных хранилищ записей и копий справочников не заводить.
- Безопасность: пароли — scrypt (`src/admin/password.ts`), сессии — случайный токен в cookie
  `__Host-admin_session` (HttpOnly, Secure, SameSite=Strict), в базе только SHA-256 токена;
  изменяющие запросы — только со своего Origin и с JSON; ограничение попыток входа.
  Демонстрационных учётных записей нет: `npm run admin:user`.
- В журнал панели и `admin_audit` — только действие и id, без персональных данных.
  Пометка ручной записи — не для реальных ФИО, телефонов и жалоб (`noteProblem` отклоняет).
- Публичный сайт живёт в группе `src/app/(site)` со своим каркасом; панель его не использует.

## VK Mini App

- Код: страница `src/app/miniapp/`, интерфейс `src/components/miniapp/`, API
  `src/app/api/miniapp/[...path]` → `src/miniapp/api.ts`, операции `src/miniapp/service.ts`,
  подпись `src/miniapp/launch-params.ts`, настройки `src/miniapp/config.ts`. Развёртывание —
  `docs/vk-mini-app-deploy.md`.
- Пациент — только `vk_user_id` из параметров запуска с проверенной подписью
  (`verifyLaunchParams`, заголовок `X-VK-Launch-Params`). VK ID из тела, адреса и других
  заголовков не принимается. Cookie и обходов авторизации нет; вне ВКонтакте — только
  пояснение. Доступ — `MINIAPP_ALLOWED_USER_IDS` (по умолчанию `VK_ALLOWED_USER_IDS`).
- Запись, отмена и перенос — только через `ClinicSchedule` (правила пациента:
  `reschedule(..., { admin: false })`), источник `miniapp`. Своей системы бронирования,
  копий расписания и справочников нет. Чужая и несуществующая запись — одинаковый 404.
- Ответы — только организационные данные (`PatientBooking`): без пометок, VK ID,
  источника, жалоб, истории бота и согласий. Отмена и перенос к другому врачу
  прекращают согласие на передачу сведений (`revokeForBooking`), как в боте и панели.
- Медицинский диалог в Mini App не переносится (решение владельца). Встраивание во фрейм
  разрешено только для `/miniapp` и только доменам ВКонтакте (`next.config.ts`).

## Меню бота и обращения к администратору

- Главное меню — три действия: «Открыть приложение» (действие `app`, во ВКонтакте —
  кнопка `open_app` Mini App; без приложения — «Записаться на приём»), «Мои записи»,
  «Администратор». Справка — текстом («какие врачи», «сколько стоит», «где клиника»);
  кнопки справки и отдельную «Записаться онлайн» не возвращать. Пояснение к кнопке
  приложения — в тексте сообщения: у кнопок ВКонтакте только подпись.
- Обращение: шаги `handoff_compose` → `handoff_consent` (dialog.ts). Текст — только
  дословно слова пациента (`requestDraft`, `composedRequest`), без резюме модели.
  Согласие — действие `hok` с меткой `draftTag` показанного текста; ничего другого
  согласием не считается. Сохранение — `RequestPort` → `RequestStore`.
- Отзыв (`hrv`, «отозвать передачу») обрабатывается и во время паузы бота.
- Тексты бота не обещают, что отказ скрывает переписку от администраторов сообщества.
