# AGENTS.md — правила проекта

Главный источник правил для людей и ИИ-агентов. Этот файл загружается в каждую сессию,
поэтому здесь только обязательное; подробности — по ссылкам и только когда они нужны.
Запуск — [README.md](README.md), этапы — [docs/roadmap.md](docs/roadmap.md).

## Начало сессии и экономия контекста

1. Прочитать этот файл и [docs/project-memory.md](docs/project-memory.md) (краткая память
   проекта). Больше ничего заранее не читать — всю документацию целиком не загружать.
2. Проверить актуальное состояние Git: `git status --short`, `git log --oneline -5`,
   текущая ветка. Память может отставать от кода: при расхождении верен код и Git, а
   документ памяти исправляется.
3. Определить компоненты, затронутые задачей, и открыть только нужное по таблице ниже.
4. Искать по репозиторию (`grep`/поиск по имени), а не читать файлы подряд; большие
   файлы — нужными фрагментами.
5. Логи, вывод тестов и сборки — сводкой (`tail`, фильтр по ошибкам), не целиком.
6. После существенного изменения обновить только затронутые документы памяти
   (`docs/project-memory.md`, `docs/architecture.md`, `docs/decisions.md`,
   `docs/current-status.md`).
7. В память и документы не записывать секреты, токены, пароли, ключи, медицинские
   сведения и персональные данные.

## Цель

Сайт компании по внедрению ИИ и автоматизации для бизнеса разных отраслей в формате
интернет-магазина цифровых решений: каталог, категории, отрасли, поиск, карточки решений
(стоимость, этапы внедрения, требования к данным и доступам заказчика, состав работ,
ограничения), ИИ-консультант по услугам, заявка на выбранное решение.
Позже: CRM, агенты поиска клиентов, автоматизация продаж, возможно онлайн-оплата.

## Согласованная архитектура (не пересматривать без причины)

- Одно приложение: Next.js 16.x (App Router) + TypeScript + Tailwind CSS, пакетный менеджер npm.
- Node.js 24 LTS (`.nvmrc`, `engines`). Основная среда разработки — Windows.
- Каталог — файлы в репозитории со строгой схемой (Zod). Категории и отрасли —
  независимые классификации.
- Цена хранится структурно: тип (фикс / «от» / по запросу), сумма в минимальных
  единицах валюты, валюта.
- Заявка — черновик заказа из позиций «решение + пакет», чтобы позже добавить корзину
  и оплату без переписывания.
- ИИ-консультант — через интерфейс сменного провайдера (`ChatProvider`) с mock-реализацией.
  Конкретный LLM-провайдер не выбирается без проверки доступности и стоимости.
- Импорты внутри `src/` — через алиас `@/*` (`tsconfig.json` → `./src/*`).

## Жёсткие правила

- Работаем небольшими этапами. После каждого этапа — проверка и подтверждение владельца.
- Демонстрационные данные явно помечаются (`isDemo` + видимая плашка «Демо»).
- Не выдумывать реальные кейсы, отзывы, гарантии и результаты от имени компании.
- Не подключать реальные платежи, не собирать реальные персональные данные,
  не разворачивать в production (только по отдельному решению).
- Отделять проверенные факты от предположений; не придумывать результаты проверок.
- Секреты не коммитятся. Пример переменных — `.env.example`, реальные — `.env.local`.
- Не добавлять зависимости без необходимости.

## Специализация: медицинские клиники

- Сайт посвящён автоматизации частных медицинских клиник. Публично — только
  `clinic-ai-administrator`, `patient-request-routing` (концепция) и
  `patient-ai-assistant` (концепция).
- Первый канал ИИ-администратора — сообщения сообщества ВКонтакте. Чат на сайте и другие
  каналы не обещаются, пока не подключены. Интеграция с МИС оценивается отдельно;
  прототип использует тестовое расписание с вымышленными врачами и пациентами.
- Остальные решения помечены `hidden: true`: файлы сохраняются, но не попадают в каталог,
  консультант, sitemap и навигацию. Публичный слой — `getSolutions()`, `getCategories()`,
  `getIndustries()`; все записи — `getAllSolutions()` (только для проверок данных).
- Тарифы: `price` — внедрение, `monthlyPrice` — обслуживание в месяц, один пакет может быть
  `recommended`; `pricingNote` — пометка «цены предварительные». Цены выводятся через
  `PackagePrice` / `formatPackagePrice`.
- Запись: если расписание клиники ведётся в нашей панели, запись подтверждается сразу
  (бот, Mini App и панель — одна база). Синхронизация с МИС или другой системой
  расписания клиники оценивается отдельно и до подключения не обещается (Р-18).
- О внешнем ИИ — прозрачно: текст сообщений обрабатывает внешний ИИ-сервис, телефоны и
  почта перед отправкой удаляются; не называть это полной анонимизацией.
- ИИ не ставит диагнозы и не назначает лечение; консультант отказывает в медицинских
  советах. Медицинские документы и жалобы — специальная категория персональных данных:
  не собираются и не хранятся до правовой оценки и подготовки инфраструктуры.
- Сценарий пациента на главной (`src/content/patient-journey.ts`) — описание будущей
  функциональности, без имитации записи или передачи данных.

## VK-бот и админ-панель — ключевое

Полные правила — [docs/rules/bot-and-panel.md](docs/rules/bot-and-panel.md), читать перед
любым изменением бота, панели или скриптов. Самое важное:

- Только вымышленная клиника и данные. Бот — административная маршрутизация, не
  диагностика: без диагнозов, лекарств, лечения и успокоения; тревожные признаки —
  правилами `safety.ts` до модели, при экстренных — сразу 103/112.
- Запись и отмена — только из сохранённого состояния и подтверждения пациента, не из
  данных кнопки и не по решению модели. Текст `OUT_OF_SCOPE_TEXT` не менять без решения
  владельца.
- Бот и панель — одна база SQLite (`BOT_DB_PATH`); миграции — только добавлением в
  `MIGRATIONS` (`src/bot/storage/sqlite.ts`), без изменения прежних.
- В журналы — без текста сообщений, ключей и персональных данных.
- VK Mini App: пациент — только `vk_user_id` из параметров запуска с проверенной
  подписью; запись — только через `ClinicSchedule` в общей базе; в ответах — без
  медицинских сведений, пометок и VK ID. Обходов авторизации не создавать.

## Роли и медицинская конфиденциальность

- Подробности, ограничения и план — `docs/medical-privacy.md`; обновление VPS —
  `docs/privacy-update-vps.md`.
- Роли сотрудников: `owner`, `admin`, `doctor` (`STAFF_ROLES`). Права — одна таблица
  `src/admin/permissions.ts`; каждый маршрут API — в `ROUTES` (`src/admin/api.ts`) с правом,
  каждая страница — `requirePage(...)`. Новый маршрут или страница без права не добавляется.
  Скрытие в меню — не защита.
- Медицинские сведения (жалоба, ответы на уточнения, реплики, состояние диалога) не
  отдаются ни одним API для `owner` и `admin`. Врач получает только краткое описание по
  своей записи и только по действующему согласию пациента (`ConsentStore`,
  `disclosure_consents`); каждая попытка — в `medical_access_log` без содержания.
- Согласие создаётся только действием пациента в боте (предпросмотр → «Передать врачу»).
  Автоматических разрешений нет.
- Обращение к администратору: только дословный текст пациента после предпросмотра и
  кнопки «Разрешаю передачу» с меткой SHA-256 этого текста (`patient_requests`,
  `RequestStore`); текст неизменяем (триггеры, проверка хэша), отзыв удаляет его; раздел
  «Обращения» — только роль `admin`, каждое открытие — в `request_access_log`. Не
  описывать согласие как защиту от чтения переписки во ВКонтакте.
- `MEDICAL_DATA_KEY` (`MedicalCipher`, AES-256-GCM с контекстом) шифрует `sessions.state` и
  содержимое согласий; без ключа передача врачу выключена.
- Переписку в сообщениях сообщества видят руководители сообщества ВКонтакте. Не писать
  в интерфейсе, документах и ответах бота, что она скрыта или конфиденциальна.
- Сотрудники создаются приглашением (одноразовый токен во фрагменте ссылки, в базе — хэш)
  или `npm run admin:user -- create <логин> --role=…`; первая учётная запись — `owner`.
  Последнего владельца нельзя отключить или понизить; смена роли завершает сессии.

## Публичный сайт — ключевое

Полные правила (каталог, заявки, консультант, SEO, дизайн-система, тексты) —
[docs/rules/site.md](docs/rules/site.md), читать перед изменением сайта. Самое важное:
заявки — тестовый режим без сохранения данных; консультант — правила, не ИИ; индексация
выключена по умолчанию; без выдуманных цифр, отзывов и кейсов; цены — только через
`PriceTag` / `formatPrice`; токены дизайна — только в `src/app/globals.css`.

## Безопасность и запуск

- Аудит, блокеры и планы (заявки, LLM) — `docs/production-readiness.md`; развёртывание —
  `docs/deployment-plan.md`; чек-лист — `docs/launch-checklist.md`. Публичный запуск —
  только решением владельца.
- Ключ клиента для ограничения частоты — только `src/lib/client-key.ts` (последний адрес
  `X-Forwarded-For`, хэш с солью). Не брать первый адрес: его подставляет клиент.
- Заголовки безопасности — `next.config.ts` (`SECURITY_HEADERS`); HSTS — на прокси.
- Ошибки страниц — `app/error.tsx` и `app/global-error.tsx`: без деталей для пользователя.

## Процесс и Git

- Приватный GitHub-репозиторий `ai-solutions-store`. Одна ветка на этап, PR в `main`.
- Merge выполняет владелец; после merge ставится тег `stage-N`.
- `package-lock.json` всегда в Git; установка в CI — `npm ci`.
- Push — в конце каждой сессии (после подтверждения владельца).

## Обязательные проверки перед PR

```
npm run lint
npm run typecheck
npm test
npm run format:check
npm run build
```

Те же шаги выполняет CI (`.github/workflows/ci.yml`) на ubuntu-latest и windows-latest.
Проверка в Linux/CI не заменяет ручную проверку на Windows-машине владельца.
